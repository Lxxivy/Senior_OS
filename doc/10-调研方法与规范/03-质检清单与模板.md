## 1. 质检总则

### 1.1 谁检

| 角色 | 检什么 | 何时 | 产出 |
| --- | --- | --- | --- |
| 作者自检 | A–F 六类清单（§2 全量） | 初稿完成、合稿后、交付前各一次 | 勾选后的清单 + 自检记录 |
| 交叉互检 | A、B、C、F 重点；D、E 抽查 | 合稿阶段 | 互检意见 + 抽检记录（§3） |
| lead 终检 | 交付验收单（§8）+ P0/P1 清零确认 | 交付前 | 签字验收单 |

交叉互检人**不得是同一篇文档的作者**；互检发现的问题由作者修复，互检人复检后关闭，不能"作者自己说改好了"就关单。

### 1.2 检什么（六类）

| 类别 | 检查对象 | 主要手段 | 主要责任 |
| --- | --- | --- | --- |
| A 内容完整性 | 赛题覆盖、七节齐全、结论非空话 | 对照 `10-02` §2 逐节核 | 作者 |
| B 数字可回源 | 每个数字能指到表号/章节 | 抽检 + `grep` 回 `build/papertext/` | 作者 + 互检 |
| C 引用有效性 | arXiv ID ↔ 本地 PDF ↔ 正文引用 | 脚本 + 人工比对 | 互检 |
| D 格式与交叉引用 | 标题层级、表格列数、代码块、文件路径 | 脚本 + 预览 | 作者 |
| E 图表渲染 | mermaid 语法、节点数、中文、图片来源 | 预览器/本地渲染 | 作者 |
| F 跨文档一致性 | 同一论文的数字/结论/术语跨文档一致 | 全库 grep + 抽查 | lead + 互检 |

### 1.3 什么时候检

1. **初稿完成**：A、B 全量；C、D、E 自检；不合格不进合稿。
2. **合稿后**：C、D、F 全量；B 抽检（§3）；重点查"数字一改、别处没改"。
3. **交付前**：六类全量 + 跑 `build/verify_docs.py` + 填验收单（§8）；P0/P1 必须清零。

### 1.4 判定与处置

- **不合格不得交付**：任一份文档 A 类有未勾选项，或 B 类抽检通过率 <100%，整批不得签字。
- **P0 清零、P1 清零**是交付的硬条件；P2 可带条件交付，但必须登记并约定修复日期（分级见 §5）。
- 同一问题**两次返工仍不过**，升级到 lead 决定：删掉该节、降级为"未覆盖"并写明风险，或换人重写。
- 所有判定以**原文/脚本输出**为准，不以"我记得论文里是这么写的"为准。

### 1.5 记录与留痕

每次质检必须留下三样东西，存放在 `build/notes/qc-<YYYYMMDD>/`：①勾选后的清单（Markdown 原样保存）；②抽检记录表（§3）；③脚本原始输出（`verify_docs.py` 的 stdout 重定向到文件）。缺任一项，lead 可拒绝签字。

## 2. 六类可勾选清单

> 用法：复制本节到 `build/notes/qc-<日期>/` 下，逐条勾选；不适用项写"不适用 + 理由"，**不得直接留空**。

### A 内容完整性（10 条）

- [ ] 赛题四条硬性要求（R1 ≥4 类可协作智能体、R2 ≥4 个可并行子任务与自动分配、R3 ≥3 对双向交互、R4 先后顺序与依赖约束）在组尾或启示节被逐条对应，并标明 R 编号
- [ ] 每篇论文七节齐全，节标题与 `10-02` §2 完全一致，无合并、无省略
- [ ] 每篇一句话结论 ≤80 汉字，且含"机制 + 量化指标"；无实验的论文明确写"无实验"
- [ ] 每篇问题与动机指出至少 1 个前人做法及其具体失效点，失效点有原文位置（图号/表号/数字优先）
- [ ] 每篇核心机制有 1 张流程图/伪代码/编号步骤，能看出输入→处理→输出
- [ ] 每篇实验节含 ≥3 个可回源数字，其中至少 1 个定位到原文表号
- [ ] 每篇局限区分【作者承认】与【本文判断】，两类各至少 1 条
- [ ] 每篇启示落到 R1–R4 或 `doc/03` 具体模块，且含"做法 + 参数 + 验收"三件套
- [ ] 组首导览表齐全（编号/论文/arXiv 与时间/一作单位/主线位置/关键词），与正文论文一一对应
- [ ] 组尾含横向对比表 + ≥5 条落地建议 + 与 AIOS 对接表（三件齐全，缺一记 P1）

### B 数字可回源（10 条）

- [ ] 抽检数字 ≥10%，每份文档不少于 5 个；文档内数字不足 5 个时全查（抽样方法见 §3）
- [ ] 抽检通过率 100%：文档值与原文值一致；不一致项已改正，或已降级为【推测】并注明
- [ ] 每个对外数字有定位（§ / Table N / Fig.N / Algorithm N）与条件四件套（模型/数据/硬件/并发）
- [ ] 速度类数字写明计时口径（墙钟/端到端/单请求/吞吐）与统计量（均值/中位数/p90/重复次数）
- [ ] 百分比、百分点、倍数未混用；换算（如时间减少 20% ⇔ 1.25×）写出了公式
- [ ] 原文未报告的指标写"未报告"；推算项标【推算】+ 公式 + 假设，且未混入论文数字
- [ ] 极值如实写："最高 2.1×"未改写成"平均 2.1×"；"13 升 5 平 0 降"未改写成"全面提升"
- [ ] 同一数字在"一句话结论 / 正文 / 数据表 / `doc/00` 速查"四处一致
- [ ] 二手来源（博客、公众号、中文解读、模型总结）未作为数字来源，只作线索且已回原文
- [ ] 结论句中没有"显著提升""大幅优于"等无数字定性替代量化（作为结论时）

### C 引用有效性（8 条）

- [ ] 每个引用论文的 arXiv ID 与 `doc/papers/<id>-<slug>.pdf` 文件一一对应
- [ ] arXiv 版本号（v1/v2/v3 或"未标"）与原文一致，未把不同版本的数据混用
- [ ] 正文引用写"标题简写（arXiv:ID）"，不只写编号、不只写"某论文"
- [ ] 引用具体数字时带表号/章节，而非只给论文
- [ ] 文末文献表字段齐全：作者 / 标题 / 出处 / arXiv 或 DOI / 本地 PDF / 抽取文本
- [ ] 代码引用带 `文件:行号`，且该路径在仓库中真实存在（如 `aios/scheduler/fifo_scheduler.py:206`）
- [ ] 工程文章引用带 URL 与抓取日期（本项目统一 2026-11-17），并注明"二手资料"
- [ ] 术语与 `10-02` §5 术语表一致，无"智能体/代理"、"编排器/调度器"混用

### D 格式与交叉引用（9 条）

- [ ] 每份文档只有一个 `#` 一级标题，标题层级不跳级（`##` 章、`###` 节）
- [ ] 所有表格分隔行 `| --- |` 的数量与表头列数一致
- [ ] 代码块全部闭合，且首行标注语言（python/powershell/json/markdown/text/csv/mermaid）
- [ ] 所有 `doc/NN` 引用指向真实存在的文件（`build/verify_docs.py` 已覆盖大部分，但见 §4.3）
- [ ] `doc/10-调研方法与规范/` 内部引用同级文件用相对链接（如 `01-检索与相似项目发现规范.md`），不写 `doc/10-…` 绝对前缀
- [ ] 文件头表格 7 字段齐全：标题 / 适用对象 / 版本 / 日期 / 维护人 / 状态 / 关联文件
- [ ] 文末有"相关文件"与"变更记录"两张表，变更记录含版本/日期/内容/作者
- [ ] 全文无 TODO、TBD、占位符、空节、空表格单元格（"未报告"不算空）
- [ ] 汉字数在区间内：单篇 1500–2000；单份文档 8000–15000（翻译类 `doc/01`、`doc/02` 除外）

### E 图表渲染（7 条）

- [ ] 每个 mermaid 块首行是合法图类型（`flowchart TD/LR`、`sequenceDiagram` 等），无裸 `mermaid` 空块
- [ ] 每个 mermaid 图节点数 ≤15（超额必须拆图）
- [ ] mermaid 中文标签用引号包裹；节点 ID 全 ASCII，无中文 ID
- [ ] `subgraph` 成对闭合，无悬空 `end`；连线标签不含未转义的括号/引号
- [ ] 图片与表格均标来源（自绘依据 arXiv:ID §x.y / 原文 Table N / URL+日期）
- [ ] 模板与命令类代码块可直接复制执行，无全角空格、无 Tab 混排
- [ ] 至少在一个 Markdown 预览器或 GitHub 页面确认图能渲染、中文不乱码

### F 跨文档一致性（8 条）

- [ ] 同一论文的数字在 `doc/00` 速查与精读文档中一致（AIOS 2.1×、152.1/74.2/77.3 s；LLMCompiler 3.74×/2.82×/1.80×）
- [ ] 同一结论在不同文档中不矛盾（如"AIOS 调度器不解析依赖"在 `doc/04`、`doc/07`、`doc/09` 一致）
- [ ] `doc/00` 索引中的文档清单与实际 `doc/*.md` 文件一致，含 `doc/articles/` 的 4 篇工程文章
- [ ] `doc/00` 的统计数字（25 篇 PDF、9 份中文文档、4 篇文章、124 MB）与实际一致
- [ ] 赛题要求编号（R1–R4）与 `doc/03` 的形式化编号一致
- [ ] 跨文档术语一致（智能体、编排器、调度器、墙钟时间、加速比等）
- [ ] 同一论文的简写与 arXiv ID 在各文档中写法一致
- [ ] "未下载两篇"（arXiv:2505.23885、2508.04482）在各文档中的标注口径一致

## 3. 数字抽检流程（可直接执行）

**第 1 步：抽样。** 把文档中的数字（含 %、×、秒、s、token、次数、金额）列出来，随机抽 ≥10% 且每份文档不少于 5 个；抽到的数字必须覆盖：1 个加速比或延迟、1 个准确率/质量指标、1 个成本或规模数字。文档内数字不足 5 个则全查。

**第 2 步：记录。** 在抽检表里填"文档值 + 上下文一句话 + 文档定位（§/表号）"，不要先看原文，避免"看原文后倒推改数"。

**第 3 步：回源。** 在 `build/papertext/<id>-<slug>.txt` 中定位。PowerShell 命令示例（在 `E:\Senior_OS` 下执行）：

```powershell
Select-String -Path "build\papertext\2312.04511-LLMCompiler.txt" -Pattern "3\.74" -Context 3,3
```

注意三个坑：① 抽取文本里数字可能是 `3.74×`、`3.74x`、`3.74 ×` 多种写法，先搜纯数字再搜表标题；② 表格被抽成乱序时，用表号（如 `Table 3`）定位后再找数字；③ 中文/符号乱码时改用 Python 读取：

```powershell
C:\Python313\python.exe -c "import io;print(io.open(r'build/papertext/2312.04511-LLMCompiler.txt',encoding='utf-8',errors='replace').read()[:3000])"
```

**第 4 步：比对。** 四态判定：`一致` / `不一致（抄错或单位错）` / `原文未报告` / `口径不同`。后两态不是"错误"，但必须在文档里显式写出"未报告"或"口径不同，不可比"。

**第 5 步：处置。**

| 判定 | 处置 | 缺陷等级 |
| --- | --- | --- |
| 一致 | 打勾 | — |
| 不一致（抄错数字/单位/表号） | 立即改文档，并 grep 全库同步 | P0 |
| 原文未报告但文档写成实测 | 改"未报告"，或降级为【推测】+ 公式 | P1 |
| 口径不同仍被比较 | 加"口径不同，不可比"或分表 | P1 |
| 回源找不到 | 回 PDF 原文核对；仍找不到则删该数字或标"出处待核"并登记 | P1 |

**抽检记录表**（每份文档一张，附在质检记录后）：

| 序号 | 文档与定位 | 数字与上下文 | 原文值 | 原文位置 | 判定 | 处理 | 经手人 | 日期 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | `doc/07` §1.5 | 76.7（10 数据集零样本平均） | 76.7 | 2305.04091 Table 2 | 一致 | — | lead | 2026-11-18 |
| 2 | `doc/01` §5.3 | 152.1 s（无调度总耗时） | 152.1 | 2403.16971 Table 2 | 一致 | — | lead | 2026-11-18 |

统计口径：抽取数 = 表行数；通过率 = "一致"行数 / 抽取数；**交付要求 100%**。

## 4. 自动化检查：`build/verify_docs.py` 的真实行为

### 4.1 运行命令与通过标准

```powershell
cd E:\Senior_OS
C:\Python313\python.exe build\verify_docs.py
echo $LASTEXITCODE
```

- **通过标准**：退出码 `0`，且输出末尾为"通过"、全程无"引用但不存在 / 无对应 PDF / 未被清单引用的 PDF / 反引号块未闭合"字样。
- **失败标准**：退出码 `1`（脚本内有 problem 即 `sys.exit(1)`）。
- 终端中文乱码时先执行 `chcp 65001`。建议把 stdout 重定向保存：`… | Out-File -Encoding utf8 build\notes\qc-<日期>\verify.txt`。

### 4.2 它实际检查了什么（4 项）

| # | 检查项 | 实现方式（源码事实） | 通过表现 | 失败表现 |
| --- | --- | --- | --- | --- |
| 1 | 字数统计 | 遍历 `doc/*.md`（**非递归**），统计 `[\u4e00-\u9fff]` 汉字数、字符数、行数 | 逐文件打印数字 | 不会失败，仅打印 |
| 2 | 文档交叉引用 | 用正则扫描正文中的 `doc/` 编号路径（`0\d` 开头）：带 `.md` 的须精确等于 `doc/` 下某文件名，不带 `.md` 的按前缀匹配 | 报告"全部存在" | 打印"引用但不存在"并计 problem |
| 3 | `doc/00` arXiv ↔ PDF | 从 `doc/00` 抽取 `arxiv.org/abs/(\d{4}\.\d{4,5})`，与 `doc/papers/` 文件名前缀比对；`2505.23885`、`2508.04482` 硬编码跳过；反向查未被引用的 PDF | 报告 27 个 id / 2 个声明未下载 / 25 个 PDF 且配对无误 | 打印"无对应 PDF"或"未被清单引用的 PDF" |
| 4 | 代码块配平 | 统计三个反引号围栏出现次数的奇偶性（奇数 = 未闭合）；顺带统计 mermaid 围栏个数 | 每份文档"ok" | 打印"反引号块未闭合" |

### 4.3 它查不到、必须人工查的

- **`doc/10-调研方法与规范/` 全部不在扫描范围**：脚本只 glob `doc/*.md`，本目录各文件（00–04）必须人工按 §2 A–F 自检。
- **数字是否与原文一致**：脚本只统计字数，不读论文；全部靠 §3 抽检。
- **表格列数、标题层级、术语一致性、空节**：脚本不检查结构。
- **mermaid 语法与渲染**：脚本只数 mermaid 围栏个数，不解析语法；节点数、中文显示必须人工预览。
- **图片是否存在、是否有来源**：脚本不检查图。
- **跨文档结论矛盾**：脚本只查路径存在，不比对内容；F 类靠人工 grep 与抽查。
- **字数是否达标**：脚本只打印，不判定 8000–15000 区间。
- **引用检查的正则边界**：引用存在性检查的正则为 `doc/(0\d(?:-[^\s`]+)?\.md|0\d)(?![0-9])`（`build/verify_docs.py:19`），只匹配 `doc/0X` 形式。`doc/10-调研方法与规范/…` 这类以 `1` 开头的子目录路径**不会**被匹配，因此不存在"误报"，但代价是根文档对 `doc/10` 的引用完全不在该校验范围内，必须人工核对；`doc/10` 内部的同级相对链接可用本仓库的 `build/check_doc10_links.py` 检查（它会解析相对路径并报告失效链接）。

**结论**：脚本是"防低级错误"的底线，不是质检全部。交付前必须"脚本通过 + 六类清单 + 抽检记录"三件齐。

## 5. 缺陷分级与返工

| 等级 | 定义 | 典型例子 | 时限 | 是否阻塞交付 |
| --- | --- | --- | --- | --- |
| P0 | 事实/数字错误，或把"宣称"写成"已实现"并进入结论 | 数字抄错、表号张冠李戴、引用不存在的文件、AIOS"支持依赖调度"写进结论 | 发现即改 | **阻塞** |
| P1 | 无源数字、结论过度、口径混用、二手当一手 | 3.74× 未写模型/任务、跨论文对比未注"不可比"、用博客数字 | 发布前改完 | **阻塞发布** |
| P2 | 格式、措辞、术语、表格列数、代码块未标语言 | 标题跳级、分隔行列数不符、术语混用一次 | 批量修，3 日内 | 不阻塞，登记后修 |

**返工流程（6 步，闭环）**：① 发现（任何人）→ ② 登记（缺陷登记表，给编号）→ ③ 指派（按写作用域指派给唯一负责人）→ ④ 修复（只改自己作用域，跨文档同步须先登记）→ ⑤ 复检（原发现人或 lead 回原文/脚本核对）→ ⑥ 关闭（记录修复版本与日期）。

**缺陷登记表字段**：编号 / 等级 / 文档与位置（§ + 行号）/ 问题描述 / 证据（原文表号、截图或脚本输出）/ 发现人 / 指派人 / 期限 / 状态（待修/修复中/待复检/已关闭）/ 复检人 / 关闭日期。

## 6. 评审问题清单（交付前自问 10 问）

评委只会问三类问题：数字哪来的、条件是什么、你的结论成立吗。以下 10 问按此设计，答不上来就回对应文件改。

1. **这个 2.1× / 3.74× 是在什么模型、什么硬件、什么并发度、什么任务上测的？原文哪张表？** 答不上 → 回 `doc/01` §5.3、`doc/07` §3.5，并按 `10-02` §3 补条件四件套。
2. **这里的"并行"是真同时执行，还是只是写了 async/线程但共享同一个推理核？** 答不上 → 看 `doc/04` Autellix、`doc/08` vLLM 节对连续批处理与抢占的描述。
3. **结论搬到 7B 端侧还成立吗？原文有 7B/8B 数据吗？** 答不上 → 在局限节写清"未报告 7B 数据，属【推测】"，并给验证方法。
4. **这是论文宣称，还是你读代码确认的？文件与行号在哪？** 答不上 → 降级为【论文宣称】，或补 `文件:行号`。
5. **这两个数能这样比吗（吞吐 vs 延迟、8B vs GPT、单卡 vs 多卡）？** 答不上 → 加"口径不同，不可比"。
6. **原文没给的数字，你写"未报告"了吗？推算的标公式和假设了吗？** 答不上 → 按 `10-02` §3 规则 4 处理。
7. **你的建议对应赛题哪条要求（R1–R4）、哪个模块？验收标准是什么？** 答不上 → 重写启示节，补齐"做法 + 参数 + 验收"。
8. **加速比的串行基线，是否与并行组只差"并发开关"一个变量（同一 Planner、同一 DAG、同一模型与硬件）？** 答不上 → 回 `doc/08` 基准协议，确认控制变量。
9. **什么时候会更慢？失败模式与兜底是什么？** 答不上 → 补 `doc/07` 的负面结论，以及 `doc/06` 的 MAST 三类失败（规格不清、协调失效、验证缺失）。
10. **同一数字在 `doc/00` 与精读文档里一致吗？引用的文件都存在吗？脚本跑过吗？** 答不上 → 跑 §4 脚本 + F 类清单。
