## 1. 为什么要规范：调研易犯的三类错误

不写规范也能"读几篇论文"，但交付物往往在评委追问时塌方。下面三类错误在本项目第一轮调研中都出现过，规范的存在就是为了在流程里设卡拦截，而不是事后靠自觉。

| 错误类型 | 典型表现 | 后果（评委/评审视角） | 本规范的拦截点 |
| --- | --- | --- | --- |
| **检索不全** | 只用一个关键词搜一次，只用中文搜，只看前 10 条结果 | "你们和 LLMCompiler 的区别是什么？"——答不上来，因为没检索到 | §3 阶段 2（术语与检索式）、阶段 3（多路召回）＋ [01](01-检索与相似项目发现规范.md) §2 检索路径矩阵 |
| **读得浅、只抄摘要** | 把论文摘要翻译一遍当精读；只读综述不读一手论文；机制讲了但说不出实现 | "这个 2.1× 是怎么测的？基线是什么？"——答不上来 | §3 阶段 5（精读 DoD：每个数字可指到表号/页码）、阶段 6（数字回源） |
| **数字无源** | 加速比来自二手博客；不同基准的数字放在一起比较；转述三次后数字变形 | 现场被要求打开原文核对，数字对不上，整页 PPT 失信 | §3 阶段 6（核对表）＋ §7 产出物规则（引用必须带原文位置） |

> **规范的边界**：本规范保证"**过程可复现、结论可核实、口径可声明**"，**不承诺"找全"**。任何检索都受平台覆盖与配额限制（见 [01](01-检索与相似项目发现规范.md) §7.3），规范的目的是让"没找到什么、为什么没找到"也变成可交付的信息。

## 2. 适用场景与调研对象分类

### 2.1 四类触发场景

| 场景 | 触发时机 | 主要产出 | 走哪些阶段 |
| --- | --- | --- | --- |
| 赛题调研（首轮） | 拿到赛题、设计未定 | 文献清单、精读文档、设计总纲 | 阶段 1–7 全走 |
| 新论文批次 | 出现新 arXiv 批次、审稿意见提到新工作 | 增量候选池、单篇笔记卡、对既有结论的修订 | 阶段 2–6（跳过问题定义，沿用已冻结的问题清单） |

### 2.2 五类调研对象与典型产出物

| 对象类别 | 典型样本 | 本项目实例 | 典型产出物 | 质量要点 |
| --- | --- | --- | --- | --- |
| 学术论文 | arXiv / 会议论文 | `doc/papers/` 下 25 篇 PDF | 单篇笔记卡、分组精读文档 | 数字回到原文表号/页码；区分"论文宣称"与"实验证明" |
| 工程文章与官方文档 | 工程博客、README、官方 docs | `doc/articles/` 下 4 篇摘要 | 中文结构化摘要（保留原始 URL 与抓取日期） | 标注"二手"；与论文/代码冲突时以论文与代码为准 |
| 开源代码库 | GitHub 仓库、SDK、示例 | `vendor/AIOS`、`vendor/owl`（见 [09](../09-AIOS与OWL代码库调研与SDK实践.md)） | 模块地图（文件＋行号）、可运行最小示例、风险清单 | 一切以仓库源码为准；文档只作线索；注明 commit |
| 竞品与相似项目 | 同类框架、竞品系统 | AutoGen/MetaGPT/CAMEL/OWL 等（作为"相似项目"评分） | 候选池、六维评分卡、差异表 | 六维分开评，不用单一"相似度"；Fork 不算独立工作 |
| 赛题与规则文本 | 赛题页、评分标准、答疑 | `doc/task.md` | 要求形式化（R1–R4）、可验收指标 | 逐条编号；"可并行""双向交互"等词必须给出可检验定义 |

> 分类即目录：论文进 `doc/papers/`，工程文章进 `doc/articles/`，代码库结论进 `doc/09`，赛题解构进 `doc/03`。新任务照此归位。

## 3. 七阶段工作流

七阶段是**串行闸门＋可回退**：每个阶段有明确 DoD，未达标不进入下一阶段；阶段 3、5 允许因新术语回退到阶段 2 补检索式。下图是主流程（虚线为回退）。

```mermaid
flowchart LR
    S1["1 问题定义<br/>与边界"] --> S2["2 术语与<br/>检索式"]
    S2 --> S3["3 多路检索<br/>与候选池"]
    S3 --> S4["4 初筛"]
    S4 --> S5["5 精读与<br/>结构化笔记"]
    S5 --> S6["6 交叉验证<br/>与数字回源"]
    S6 --> S7["7 写作、质检<br/>与复盘"]
    S5 -. "发现新术语" .-> S2
    S4 -. "进池不足" .-> S3
```

### 3.1 阶段 1：问题定义与边界

| 项目 | 内容 |
| --- | --- |
| 目标 | 把赛题/设计需求翻译成 **≤10 个可检索、可判定的问题**，并明确本轮"不做什么" |
| 输入 | [task.md](../task.md) 的四条要求与评分标准；[03](../03-赛题对标与多智能体系统设计方案.md) 已形式化的 R1–R4；上一轮未解问题；时间预算 |
| 关键动作 | ① 逐条抄录要求并编号（R1–R4）② 每条要求转成"要回答的问题"（如"AIOS 调度器能否真正并行？""4 种 agent 是否异构？"）③ 列出"不做什么"（本项目：不做 GUI 自动化、不做多机分布式、不做模型训练）④ 为每个问题指定**期望证据类型**（论文数据／代码行／演示日志） |
| 产出物 | 一页《调研问题清单》：问题编号｜对应要求｜期望证据｜优先级（P0/P1/P2） |
| 完成标准 DoD | 每个问题都能补全句式"如果找到 X，就算回答"；"不做什么"≥3 条；问题数 ≤10（超了说明没聚焦） |
| 常见失误 | 直接从关键词开搜；问题写成"了解一下多智能体"（无法判完成）；不写边界，越搜越散 |

### 3.2 阶段 2：术语与检索式构建

| 项目 | 内容 |
| --- | --- |
| 目标 | 产出**可直接粘贴执行**的术语资产与检索式，而不是"大概知道搜什么" |
| 输入 | 问题清单；已读材料中出现过的术语（赛题原文、AIOS 论文、综述） |
| 关键动作 | ① 每个 P0 问题建中英同义词表（主词／同义变体／缩写／排除词）② 每个概念组 3–8 个变体 ③ 写 3–5 条检索式并**试跑**，记录命中量级 ④ 识别"同名不同义"（`agent`＝LLM agent／强化学习 agent；`scheduler`＝OS 调度器／任务调度器） |
| 产出物 | 术语表（中英对照＋排除词）＋检索式 v1（含平台、限定符、预期命中量级） |
| 完成标准 DoD | 每条检索式都实际执行过并留下命中数；同义词表覆盖 ≥4 组；每组有 ≥1 个排除词 |
| 常见失误 | 只用中文搜；用整句当关键词；一个检索式塞 5 个概念（AND 过窄，命中为 0） |

> 同义词表模板、布尔与短语规则、4 组真实示例见 [01](01-检索与相似项目发现规范.md) §3。

### 3.3 阶段 3：多路检索与候选池

| 项目 | 内容 |
| --- | --- |
| 目标 | 用**多条独立路径**召回，形成可追溯的候选池；单条路径的遗漏由其他路径补 |
| 输入 | 检索式 v1；[01](01-检索与相似项目发现规范.md) §2 的路径矩阵（a 关键词／b 引用链／c GitHub 代码与 README／d 现成相似项目工具／e 术语扩散） |
| 关键动作 | ① 每条路径各跑一轮，**每次检索都写日志**（查询→命中数→新增入池）② 候选逐条入池（编号、来源、六维初评、入池理由）③ 同步去重（同 DOI / arXiv 版本 / Fork 镜像） |
| 产出物 | 候选池表（≥20 条进池）＋ 检索日志 CSV |
| 完成标准 DoD | ≥3 条不同路径有命中；每条候选都有可点击来源链接与一句话入池理由；日志无空行；去重后无重复条目 |
| 常见失误 | 只跑一条路径就宣布"没有相关工作"；不记日志导致无法复现也无法证明"找过"；把 Fork 当独立项目 |

### 3.4 阶段 4：初筛

| 项目 | 内容 |
| --- | --- |
| 目标 | 用最低成本把候选池从 40+ 砍到可精读规模（10–15），并让每一次淘汰都有记录 |
| 输入 | 候选池；每条的标题、摘要、年份、venue、可获取性 |
| 关键动作 | **四筛**：① 标题筛（是否同一问题域）② 摘要筛（方法是否涉及目标机制）③ 年份与 venue 筛（是否被后续工作取代）④ 可获取性筛（有无 PDF／开源代码）。结果分**三态**：进池／观察／淘汰，淘汰必须写一句理由 |
| 产出物 | 状态列填满的候选池＋精读队列（≤15 条，按优先级排序） |
| 完成标准 DoD | 每条淘汰有理由；"观察"占比 ≤20%（否则等于没筛）；精读队列每条都标了"要从中拿什么" |
| 常见失误 | 按标题拍脑袋；把"观察"当垃圾桶；因为 PDF 打不开就淘汰高相关论文（正确做法：读摘要＋找引用它的二手总结，并标注证据等级） |

### 3.5 阶段 5：精读与结构化笔记

| 项目 | 内容 |
| --- | --- |
| 目标 | 把候选转成**可引用、可判断、可复现**的结构化笔记，而不是读后感 |
| 输入 | PDF（`doc/papers/`）与抽取文本（`build/papertext/`，由 `pdftotext -layout` 生成）；精读队列 |
| 关键动作 | ① 先读摘要／图表／结论，判断是否值得全文 ② 全文按"背景—方法—实验—局限"四段拆 ③ 数字记录到**表号/页码** ④ 摘 3 条可复用机制并写"对本项目的含义：可用／需改造／不可用" ⑤ 跨篇对照同类机制 |
| 产出物 | 单篇笔记卡（1 页）＋分组精读文档（如 [04](../04-智能体操作系统内核与并发服务-精读.md)–[08](../08-评测基准与端侧推理加速-精读.md)） |
| 完成标准 DoD | 每个关键数字能指到原文表号/页码；每条机制有明确判断；无"该方法很好"式空话；未给出的内容显式写"论文未给出" |
| 常见失误 | 只读摘要就写"精读"；纯转述不下判断；数字转手多次不回源；把综述当一手证据 |

> 精读笔记模板、"一页卡片"字段与合格/不合格示例见 [02-精读与写作规范](02-精读与写作规范.md) §2；卡片空壳、抽检表与交付验收单见 [03-质检清单与模板](03-质检清单与模板.md) §7；已交付的成品范式可直接照 [04](../04-智能体操作系统内核与并发服务-精读.md)–[09](../09-AIOS与OWL代码库调研与SDK实践.md) 的章节结构写。

### 3.6 阶段 6：交叉验证与数字回源

| 项目 | 内容 |
| --- | --- |
| 目标 | 消除二手转述误差，让每一个对外引用的数字都能在 30 秒内被评委核对 |
| 输入 | 精读笔记草稿；PDF/抽取文本；[00](../00-调研总览与索引.md) §6 的关键结论清单 |
| 关键动作 | ① 关键数字逐个回原文定位（`grep` 抽取文本 + 回看 PDF 对应页）② 同一机制在 ≥2 篇论文出现时写出异同（如上下文切换：MemGPT vs AIOS）③ 标注版本（arXiv v1/v2 与会议版数字可能不同）④ 无法核对的降级为"据 X 转述"并注明 |
| 产出物 | 数字核对表（数字｜原文位置｜核对人｜日期）＋修订后的笔记 |
| 完成标准 DoD | 所有对外数字 100% 有原文位置；抽查 10 个数字全部一致；差异项已注明；无"来源不明"的数字进入交付文档 |
| 常见失误 | 相信二手博客的加速比；把不同基准/不同硬件的数字并列；忘记正式版修正了预印本数字 |

### 3.7 阶段 7：写作、质检与复盘

| 项目 | 内容 |
| --- | --- |
| 目标 | 交付可评审文档，并把本轮经验变成下一轮可复用的资产 |
| 输入 | 笔记、核对表、问题清单、检索日志 |
| 关键动作 | **A 写作**：结论先行、一图一表、术语统一、引用带原文位置；**B 质检**：交叉引用全部可点、表格列数一致、占位符扫描、事实抽查 10%、数字与核对表比对；**C 复盘**：检索日志归档到 `build/notes/`、术语表更新、写 3 条教训（哪条路径最有效／哪类候选最耗时／哪个环节超预算） |
| 产出物 | 交付文档＋质检记录＋复盘记录（≥1 条可执行改进） |
| 完成标准 DoD | 交叉引用 0 失效、0 占位符、抽查一致率 100%（或差异已列明）；本轮检索日志已归档；教训可被下一轮直接执行 |
| 常见失误 | 写作与检索脱节（文中引用找不到出处）；质检只看错别字；复盘写成"下次更努力"（不可执行） |

## 4. 角色与分工

### 4.1 五个角色

| 角色 | 核心职责 | 该角色的 DoD | 兼任约束 |
| --- | --- | --- | --- |
| 调研负责人（lead） | 定问题、切分任务、裁决冲突、对外口径、终审 | 问题清单签署；所有交付物过验收；冲突有书面结论 | 不兼任质检员（终审与质检分离） |
| 检索员 | 跑路径、维护候选池与检索日志、去重 | 每轮日志完整；候选池状态无空值；每条候选有来源链接 | 可由精读员兼 |
| 精读员 | 读全文、写笔记卡、抽可复用机制 | 数字可回源；机制有"可用/需改造/不可用"判断 | 可由检索员兼 |
| 写作者 | 成文、统稿、术语与格式一致 | 结构与提纲一致；交叉引用有效；无空话 | 可由精读员兼 |
| 质检员 | 交叉引用、数字抽查、反模式检查、出具质检单 | 出具质检单（问题清单＋是否放行）；抽查记录留痕 | **不得与被检文档作者为同一人**（硬约束） |

### 4.2 规模示例：1 名主控 + 6 名并行子代理

本项目首轮调研的实际编队如下。它只是一个**规模示例**，不是唯一正确编队——判据是"写入范围互斥、每人有独立交付物"。

| 单元 | 负责范围 | 交付物 | 写入边界 |
| --- | --- | --- | --- |
| 主控（lead） | 阶段 1、2、6 终审；阶段 7 统稿与质检 | 问题清单、索引、设计总纲 | 汇总类文档 + 任务板 |
| 子代理 1 | 内核与并发（4 篇） | `doc/04` | 仅该文件 |
| 子代理 2 | 协作框架（5 篇） | `doc/05` | 仅该文件 |
| 子代理 3 | 失败模式与拓扑（3 篇） | `doc/06` | 仅该文件 |
| 子代理 4 | 任务分解与并行（5 篇） | `doc/07` | 仅该文件 |
| 子代理 5 | 评测与推理加速（6 篇） | `doc/08` | 仅该文件 |
| 子代理 6 | 代码库调研（AIOS/OWL）与工程文章 | `doc/09`、`doc/articles/` | 仅这些文件 |

**并行协作的三条硬规则**：① 一人一文件，写作用域不相交，主控只做汇总不代写；② 每份任务在共享任务板上"先 claim、完成后 complete"，并记录预期写入范围；③ 交叉引用与术语由主控统一，子代理不得擅自改他人文件。

## 5. 时间与规模预算

### 5.1 单位耗时参考值

| 工作项 | 单位耗时 | 本项目参考 | 备注 |
| --- | --- | --- | --- |

| 单篇全文精读＋笔记卡 | 40–60 分钟 | 25 篇约 20 小时 | 含数字回源 |

> 排期按"并行单元数 × 单单元 1 个工作日"估算，不按页数。**瓶颈通常不是读，而是主控的汇总与质检**，主控预算需留足 20%。

### 5.2 按截止时间裁剪

| 预算档位 | 文献量 | 文档量 | 并行单元 | 预计耗时 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 完整 | 25 篇 | 6 份 | 6 | ≈2 个工作日 | 本项目首轮采用 |
| 标准 | 12 篇 | 3 份 | 4 | ≈1 个工作日 | 保证五组各至少 2 篇 |

**不可裁剪的底线**：① 赛题点名的 2 篇（AIOS 与多智能体协作综述）必须全文读；② 每个对外数字必须回源；③ 相似项目检索至少两条路径。

**裁剪顺序（先保后弃）**：点名 2 篇 → 并行机制（LLMCompiler）→ 失败模式（MAST）→ 服务并发（vLLM/SGLang）→ 评测基准 → 各框架细节 → 理论/愿景类。裁掉的内容在文档中显式写"本轮未覆盖，风险是……"，不许假装读过。

## 9. 常见问题 FAQ

**Q1：时间不够，读不完怎么办？**
按 §5.2 裁剪：先保点名 2 篇＋机制/失败/评测各 1 篇，共 5 篇；其余降级为"读摘要＋记入候选池观察态"。**不允许**假装读过——交付文档显式写"本轮未覆盖 X，风险是 Y"。

**Q2：只找到中文二手解读怎么办？**
二手只能作线索，不能作证据。做法：① 用二手文章里的论文标题/作者名反查一手 PDF；② 查不到就标注"（二手，未实测）"并降低证据等级；③ 关键结论必须有一手来源，否则不进 §6 结论速查。

**Q3：论文没给具体数字（如没报加速比）怎么办？**
在笔记里显式写"论文未给出"，不要用"显著提升"转写成数字。若必须量化，标为"我方估算"并写出估算依据与假设，与论文数字分栏呈现。

**Q4：工具打不开/下载失败怎么办？**
先换通道：pwsh 直连 HTTPS 失败时用 Python `urllib`（本项目实测可行，见 [00](../00-调研总览与索引.md) §8）；PDF 抽取用 `pdftotext -layout`。仍失败则：① 用摘要＋引用它的论文间接获取；② 在候选池标"不可获取-已尝试 N 次"；③ 不许因下载失败而静默删除候选。

**Q5：怎么判断该停止检索了？**
用 [01](01-检索与相似项目发现规范.md) §5.4 的停止条件：连续两轮新增高相关 <2 篇；核心 5 篇的引用链查完；gold set 的 Recall@K 不再上升；时间预算用尽。四个条件满足任意两个即可停，并在日志里写"停止依据"。

**Q6：如何避免与队友重复劳动？**
① 共享任务板上先 claim 再干，任务写清"检索哪组、写哪个文件"；② 候选池与检索日志是**共享单一副本**，不各存一份；③ 写作用域不相交（一人一文件）；④ 主控在每日汇总时合并去重，重复条目标注"已由 X 覆盖"。

**Q7：候选池越搜越大，怎么控制？**
候选池允许大（≥40），但**精读队列必须小**（≤15）。控制点在阶段 4：四筛后只留能回答 P0 问题的条目，其余留在"观察"态，不投入精读成本。

**Q8：怎么证明"我们真的调研过"而不是拍脑袋？**
出示三样东西：检索日志（查询→命中→新增）、候选池（含淘汰理由）、数字核对表（数字→原文位置）。这三样也是答辩被追问时的兜底材料。
