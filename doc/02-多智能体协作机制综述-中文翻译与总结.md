## 0. 速览 TL;DR

- **一句话总结**：这篇综述把「LLM 多智能体系统」（LLM-based Multi-Agent Systems, MAS）里最容易被含糊带过的部分——**智能体之间到底怎么协作**——拆成五个可操作的维度（参与者 actors、类型 types、结构 structures、策略 strategies、协调与编排 coordination & orchestration），并用一个统一的协作通道（collaboration channel）形式化框架把已有工作收拢到同一张地图上。
- **综述范围**：从多智能体系统、LLM、协作式 AI（collaborative AI）三条脉络出发，界定智能体与协作系统的数学定义，系统梳理以 2022–2024 年为主的既有工作（参考文献编号至 [166]），覆盖合作／竞争／竞合三类协作类型、规则／角色／模型三类协作策略、集中／分散／分层三类通信结构、静态／动态两类编排架构，并落到 5G/B6G 与工业 5.0、问答与自然语言生成、社会与文化三个应用域。
- **提出的分析框架**：五维度——**actors（参与者）/ types（类型）/ structures（结构）/ strategies（策略）/ coordination protocols（协调协议）**；其核心创新是把「协作通道」$c_j$ 当作一等公民：只要参与者、类型、结构、策略中任一属性不同，就算作不同的通道，因此一个系统可以同时容纳多条异构通道（例如辩论通道 + 研究协作通道）。
- **主要结论**：① 协作不是免费的，通信开销、级联幻觉（cascading hallucination）、单点失败都会随智能体数量放大；② 设计不良的多智能体系统会被「强提示的单智能体」反超（文中引用 [128] 的实证）；③ 现有系统高度集中在「基于角色 + 集中式/分散式」这一小块配置空间，竞争、竞合、分层、模型驱动策略仍是稀疏区；④ 领域知识往往决定编排架构该静态还是动态。
- **适合谁读**：正在搭多智能体框架的工程师（想知道该选哪种拓扑、什么时候别上多智能体）、做 agent 评测的研究者（想知道基准缺什么）、以及需要向非技术同事解释「多智能体为什么有时更差」的技术负责人。

## 1. 摘要（全译）

随着大语言模型（Large Language Models, LLMs）的最新进展，智能体式 AI（Agentic AI）在真实应用中表现惊人，并正朝着由多个 LLM 智能体协同感知、学习、推理与行动的方向演进。这些**基于 LLM 的多智能体系统**（LLM-based Multi-Agent Systems, MASs）使成组的智能体能够大规模地协调并集体求解复杂任务，从而完成从孤立模型到以协作为中心的方法论的转变。

本工作对 MAS 的**协作侧面**做了广泛综述，并提出了一个**可扩展的框架**以指导未来研究。我们的框架依据若干关键维度来刻画协作机制：**参与者**（actors，即所涉智能体）、**类型**（types，如合作 cooperation、竞争 competition 或竞合 coopetition）、**结构**（structures，如对等 peer-to-peer、集中 centralized 或分散 distributed）、**策略**（strategies，如基于角色 role-based 或基于模型 model-based），以及**协调协议**（coordination protocols）。通过对现有方法学的梳理，我们的发现可作为基础，用于祛魅（demystify）并推进基于 LLM 的 MAS，使其面向更智能、更协作的解决方案，以应对复杂的真实用例。

此外，本文还考察了 MAS 在不同领域中的多种应用，包括 5G/6G 网络、工业 5.0（Industry 5.0）、问答（question answering）以及社会与文化场景，展示了其更广泛的采用与更深远的影响。最后，我们总结了关键的经验教训、开放挑战以及面向**人工集体智能**（artificial collective intelligence）的潜在研究方向。

**CCS 概念**：• 一般性与参考性 → 综述与概览；• 计算方法学 → 多智能体系统；自然语言生成；神经网络。
**附加关键词与短语**：人工智能、大语言模型、多智能体协作。

## 2. 引言

### 2.1 动机

LLM 的最新进展改变了人工智能，使其能够完成创意写作、推理、决策等复杂任务，可以说已达到可与人类水平相比的程度 [156]。尽管这些模型在个体层面展现出显著能力，它们仍受制于若干**内在局限**：幻觉（hallucination）[57]、自回归本性（autoregressive nature，例如不具备「慢思考」能力）[49]，以及缩放定律（scaling laws）带来的成本与能力边界 [55, 69]。

为应对这些挑战，**智能体式 AI**（agentic AI）把 LLM 当作「大脑」或编排器（orchestrator），将其与外部工具和议程（例如规划）集成，使基于 LLM 的智能体能够采取行动、解决复杂问题，并与外部环境交互、从中学习。更进一步，研究者正日益探索**横向扩展**（horizontal scaling）——用多个基于 LLM 的智能体协同工作，走向集体智能。这一路线与多智能体系统（MAS）和协作式 AI 的既有研究相吻合：二者都聚焦于让成组的智能体协调、共享知识并集体求解问题。两条脉络的汇合催生了基于 LLM 的 MAS，它利用多个 LLM 的集体智能来应对复杂的多步挑战 [118]。

MAS 的灵感并不止于技术进步，它扎根于**人类集体智能**——例如「心智社会」（society of mind）[87] 与「心智理论」（theory of mind）[45]。人类社会擅长利用团队协作与专业化分工来实现共同目标，从日常琐事到科学发现皆然。类似地，MAS 被设计来模拟这些原则，让 AI 智能体通过组合各自的长处与视角实现有效协作。

基于 LLM 的 MAS 可以拥有多条特征各异的**协作通道**（collaboration channels），如图 1 所示。MAS 已在多个领域取得显著成功，通过专业化智能体之间的协作与协调，增强了单个 LLM 的能力。这类系统把任务分配给各智能体，使智能体能够共享知识、执行子任务，并让各自努力对齐到共同目标。

MAS 的潜在收益具有变革性，原文列举了四点：

1. **知识记忆**（knowledge memorization）：使分布式智能体各自保留并共享多样的知识库，而不必让单一系统过载 [51, 154]。
2. **长期规划**（long-term planning）：通过在智能体间委派任务，支撑跨长程交互的持续问题求解 [58]。
3. **有效泛化**（effective generalization）：汇集多个具备专门提示／人格（prompts/personas）的模型的专长，使其能比独立模型更有效地应对多样问题。
4. **交互效率**（interaction efficiency）：通过专业化智能体并行处理子任务，加速复杂多步任务的解决。

MAS 追求的是**集体智能**：多个智能体组合后的能力超过其各自贡献之和 [24]。

而实现有效 MAS 的**主要焦点之一，正是协作机制**（mechanisms of collaboration）[33, 74, 75, 97, 132]。协作机制推动了一场转变：从传统的、孤立的模型，转向强调交互的方法——使智能体能够连接、协商、决策、规划并联合行动，从而在集体场景中推进 AI 的能力。**深入理解协作机制在 MAS 中如何运作，是释放其全部潜能的关键。**

> **图 1 的场景（译文）**：一个问答型多智能体协作系统。用户提问「为什么加密货币比法币更可持续？」。第一条通道里，两个 LLM 通过**辩论**互相对抗：「支持智能体」（Support Agent）主张「加密货币总是更可持续，因为……」，而「反对智能体」（Oppose Agent）回应「我不同意，但我需要更多信息」。第二条通道里，反对智能体转而**合作**，向两个研究智能体（环境影响研究智能体 1、稳定性研究智能体 2）发出查询，最后给出「最终回复」。图中标注：竞争、基于规则、分散化的通道；合作、基于角色、集中化的通道。原文说明：第一条通道中两个 LLM 以轮次策略（turn-based strategy）就用户输入展开辩论；第二条通道中反对智能体与合作地利用研究智能体的信息，并向用户给出最终回复。

这一个例子已经把本文框架的五个维度全部演示了一遍：同样是「两个智能体在说话」，但**类型**（竞争 vs 合作）、**结构**（分散 vs 集中）、**策略**（规则驱动 vs 角色驱动）都不同，因此它们是**两条不同的协作通道**，而不是同一条通道的两种说法。这个「通道多元并存」的视角，是全文分析框架的种子。

### 2.2 现有工作与本文贡献

由于基于 LLM 的多智能体协作系统重要且正逢其时，此前已出现若干相关综述。然而这些工作往往未能充分处理 LLM-based MAS 的**协作侧面与协作机制**——而这恰恰是让智能体有效走向共同目标的关键。原文用表 1 做了对比（评价维度：是否聚焦多智能体协作系统、是否审阅 MAS 中的协作侧面与机制、是否提出面向 MAS 的通用框架、是否审阅真实世界应用；取值为 High / Medium / Low / None）。

原文的批评逐条如下：

- **[47, 107, 136] 偏重单智能体系统**，只在表层触及多智能体协作。其中 [136] 提出了 LLM 智能体的三组件框架——**大脑（brain）、感知（perception）、行动（action）**，强调把 LLM 用作智能体的大脑，并利用输入模态整合、提示（prompting）、检索（retrieval）、工具使用等技术；但其对多智能体协作的讨论仅限于智能体的行为与人格（behaviors and personalities），缺少对「使智能体得以协同工作的机制」的探讨。
- **[47]** 综述了 LLM-based MAS 已成功应用的领域与场景，刻画了这些系统的通信结构（分层 layered、分散 decentralized、集中 centralized、共享消息池 shared message pools），但未触及协作的其他特征，例如类型、策略或协调架构。
- **[82]** 聚焦协作策略，将其分为合并（merging）、集成（ensemble）、合作（cooperation）三类；虽讨论了这些策略如何应用于 LLM，并把「合作」扩展到传统融合技术之外，却忽略了其他关键协作机制（如竞争与竞合），也忽略了流行协作类型之外的维度。
- **[120]** 提出了通过 MAS 增强 LLM 能力的通用框架，并说明 Auto-GPT 等工具如何对齐其框架；但其协作机制仍停留在概念层面，缺少细化的实现与刻画。
- **[50]** 关注如何配置 LLM 以利用多样能力与角色（如集成记忆与信息检索组件），其对多智能体协作的探索主要集中于规划与编排架构，强调基于智能体角色与专长的全局／局部任务规划。
- **[46]** 把焦点收窄到 LLM-based MAS 在**基于智能体的建模与仿真**（agent-based modeling and simulation）中的应用，讨论了环境感知、人类对齐、行动生成与评估等挑战；虽对仿真类应用有洞见，却缺少对深层协作机制的更广阔视角。
- 类似地，**[68]** 面向数字孪生（digital twin）应用做综述，**[52, 70]** 聚焦软件工程领域。

据此，原文指出的**空白**是：对 LLM-based MAS 的协作侧面与机制缺乏充分探索，而这些机制对「让智能体协同走向共同目标」至关重要。

本文的目标是提供一幅关于多智能体协作系统中 LLM 智能体之间**协作基础**的完整图景。以协作为主线，本研究依据以下方面刻画智能体间的协作：**参与者**（actors，涉及的智能体）、**类型**（type，如合作、竞争或竞合）、**结构**（structure，如对等、集中或分散）、**策略**（strategy，如基于角色、基于规则或基于模型），以及协作中的**协调层**（coordination layer）。作者强调促成有效协作的**机制与「诀窍」（know-how）**，识别 MAS 设计的关键特征与趋势。通过对现有方法的综述与对开放挑战的识别，这些发现被综合为一个连贯的框架，作为未来研究的基础，推进 LLM 与 MAS 的整合，并为更具适应性、更智能、更协作的 AI 系统铺路。

**四项主要贡献**（原文条目直译）：

- **LLM-based MAS 的协作侧面与机制**：聚焦 LLM 多智能体协作的运行机制，强调实现有效协作所需的「诀窍」，包括协作类型、策略、通信结构与协调架构。
- **面向 LLM-based MAS 的通用框架**：提出一个综合性框架，整合 MAS 的多样特征，使研究者能够理解、设计与开发多智能体协作系统。
- **真实世界应用综述**：考察 LLM-based MAS 在各领域的实际实现，突出其实际应用、成功之处与局限。
- **经验教训与开放问题讨论**：识别 MAS 发展议程中的关键挑战（如集体推理与集体决策），并勾勒潜在研究方向。

## 3. 背景知识

### 3.1 多智能体（AI）系统

MAS 是由多个**相互作用的智能体**构成的计算机化系统。原文给出四个关键组件：

- **智能体（Agents）**：核心行动者，拥有角色、能力、行为与知识模型。学习、规划、推理与决策等能力为智能体乃至整个系统注入智能。
- **环境（Environment）**：智能体所处的外部世界，智能体可感知它、作用于它。环境可以是仿真的，也可以是物理空间，如工厂、道路、电网等。
- **交互（Interactions）**：智能体之间的通信通过标准的**智能体通信语言**（agent communication languages）进行。依据系统需要，交互涉及合作、协调、协商等。
- **组织（Organization）**：智能体或者具有层级化控制，或者依据涌现行为（emergent behaviors）自行组织。

MAS 能够求解单个智能体或单体系统（monolithic system）难以或无法求解的问题 [37]。智能体协作完成任务，同时因其固有的学习与自主决策能力而具备更高灵活性。智能体利用与邻居智能体或与环境的交互来学习新的情境与动作；随后依据所学知识决定并执行作用于环境的动作，以完成被分配的任务 [43]。正是这种灵活性使 MAS 适用于计算机科学、土木工程、电气工程等多学科的问题求解。

原文进一步列出 MAS 的**四项显著特性**：

- **灵活性与可扩展性（Flexibility and Scalability）**：MAS 可通过增加、删除、修改智能体来灵活适应变化的环境，因而在求解复杂问题时高度可扩展。
- **鲁棒性与可靠性（Robustness and Reliability）**：控制的分散化使得部分组件失效时系统仍能持续运行，从而带来更强的鲁棒性与容错能力。
- **自组织与协调（Self-Organization and Coordination）**：智能体可依据涌现行为规则自组织，实现分工、协同决策与冲突消解。
- **实时运行（Real-time Operation）**：无需人类监督即可做出即时情境响应，支撑灾害救援、交通优化等应用。

MAS 的效率源自其内在的**分工**：复杂任务被切分为多个更小的任务，每个交给一个不同的智能体。相应地，处理与能耗等开销被摊销到多个智能体上，这往往比「用一个强大单体去解整个复杂问题」成本更低。每个智能体可用任意水平的预置知识来求解被分配的任务，这带来了高灵活性；而 MAS 采用的分布式问题求解方式又赋予了高可靠性——当某个智能体失效时，任务可以被 readily 重新分配给其他智能体。

### 3.2 大语言模型

LLM 由 Transformer 架构 [127] 的发展所驱动，代表自然语言处理（NLP）与 AI 的一次重大跃迁。这类模型——如 OpenAI 的 GPT [4]、Meta 的 LLaMA [124]、Google 的 Gemini 系列 [123]——在大规模文本语料上训练，依赖具有数十亿乃至有时数万亿参数的大规模人工神经网络。其规模带来了语言理解、生成与任务特定应用上的突破 [38, 93, 101, 110, 125]。

LLM 的**定义性特征**是其规模，以及**涌现能力**（emergent abilities）现象——当模型在参数量上超过某个阈值时涌现出的能力。这些涌现行为使 LLM 能够求解其未被显式训练过的任务，例如类比推理（analogical reasoning）与零样本学习（zero-shot learning）：模型无需额外微调即可应对新问题 [113]。近年来 GPT-3、ChatGPT 等模型的发布使这些能力为公众所可及，推动了学术界与工业界对「如何优化、扩展并保障 LLM 的真实世界使用」的研究激增 [42]。

尽管创新令人期待，LLM 并非没有问题。当真实世界知识发生变化时其性能会退化，这促使研究者关注在不从头重训的前提下让模型与最新信息对齐 [19, 28]。此外，LLM 开发的地缘政治与伦理影响已成为政策制定者的焦点，尤其是关于所需算力以及被恶意行为者滥用的可能 [76, 86]。

LLM 正日益被用作 MAS 中个体智能体的「大脑」，为每个智能体带来精细的推理与语言能力。借助 AgentVerse 等框架，LLM 通过允许智能体推断任务、基于情境感知做决策，甚至展现协作与协商等涌现社会行为，增强了智能体的自主性 [24]。然而，LLM 在单智能体任务上表现优异，在多智能体场景下其局限便暴露出来——那里的协调、通信与决策复杂度更高。**级联幻觉**（cascading hallucinations）——一个错误输出导致错误不断累积——这类问题对持续的多智能体交互构成挑战。不过，MetaGPT 等框架引入了元编程（meta-programming）技术，在智能体交互中嵌入结构化工作流与流程，以分解并攻克复杂问题，从而缓解这些问题 [56]。此外，Consensus-LLM 项目中测试的共识寻求机制表明，LLM 能够在动态环境中就共同目标进行协商与对齐 [21]。这些工作展示了 LLM 作为中心决策组件的潜力，也凸显了 LLM 适应其他 LLM 智能体策略的能力——这在多种应用中可能具有基础性意义。

### 3.3 协作式 AI

**协作式 AI**（Collaborative AI）通常指被设计为与其他 AI 智能体或人类协同工作的 AI 系统 [27]。它源自两条主要研究脉络：其一，AI 的进步带来了越来越有效的人类可用工具，以及对「能与其他智能体（人类或 AI 模型）协作的 AI 系统」日益增长的需求；其二，人们认识到 AI 模型之间的主动协作可以显著提升效率与效果。该研究横跨 MAS、人机交互（human-machine interaction）、博弈论（game theory）与自然语言处理等多个领域 [1, 14, 26, 29]。通过整合这些技术，协作式 AI 有潜力催生具有深远经济与社会影响的新应用 [85, 96]。

**协作**是使 AI 智能体能够彼此交互与工作的关键。最直接的协作机制是两个模型朝着共同目标合作。然而，虽然合作是一个基础侧面，**协作的光谱远比这更宽**，还包含竞争与竞合等更高级的机制。协作式 AI 带来了一场转变：从传统的孤立模型，转向强调协作的方法。新方法学被提出，使智能体能够交互、协商、决策、规划并联合行动，在集体场景中推进 AI 的能力 [30]。

协作式 AI 的一大主题是 MAS 研究，它聚焦智能体之间的交互与涌现的协作行为。更具体地说，MAS 关心的是能够在复杂环境中相互学习、适应与协作、走向共同目标的智能体（或 AI 模型）。另一方面，LLM 的快速进步开启了新的可能：LLM 已被证明可以充当 MAS 中智能体背后的「大脑」，驱动这样一类应用——智能体不仅执行任务，还与外部工具（如互联网搜索、计算器）交互，更重要的是**彼此交互** [47]。然而，LLM 并非天生被设计与训练用于彼此通信，这在该领域留下了大量潜在应用与开放问题。LLM 与 MAS 的融合，为后续探索与创新许诺了激动人心的机会。

本工作提供了一幅关于 MAS 中 LLM 智能体之间协作侧面的完整图景，强调使智能体有效走向共同目标的机制。通过综述现有方法并识别这一新兴领域的开放挑战，作者提供了一个超越传统「合作」的独特视角，把辩论（debate）、协商（negotiation）、竞争（competition）等多样协作模式纳入其中。这种对协作动力学的深入聚焦，使本工作成为推进 LLM 与 MAS 整合的重要资源。

## 4. 多智能体协作的概念界定

本章引入 LLM-based 多智能体协作系统的主要概念，基于近期研究洞见界定智能体、系统与协作机制的关键组件。

### 4.1 智能体与协作系统定义（含形式化定义与符号表）

一个智能体可数学地表示为 $a = \{m, o, e, x, y\}$，各符号含义如下（这也是全文的符号基础）：

- **模型 $m = \{\text{arch}, \text{mem}, \text{adp}\}$**：即 AI 模型，由架构（arch）、智能体专属记忆（mem）与可选适配器（adp）构成。适配器是自适应智能模块，使智能体能够通过**推测解码**（speculative decoding）与**参数高效适配器**（parameter-efficient adapter）等机制从他人处吸纳额外知识，从而进一步丰富模型的响应能力 [40, 72, 98]。在 LLM 智能体的情形下，架构 arch 是一个语言模型，而智能体专属记忆 mem 通常就是系统提示（system prompt）$r$。
- **目标 $o$**：智能体的目标或目的，引导其在系统中的行动。例如在问答任务中，目标是让生成的答案与真值之间的交叉熵最小。
- **环境 $e$**：智能体运行所处的状态或条件，即环境或上下文。在 LLM 中，通常由 token 数量约束的上下文窗口来体现。
- **输入 $x$**：输入感知，如文本或传感器数据。在 LLM 中，$x$ 被编码为 token 序列。
- **输出 $y$**：相应的动作或输出，由函数 $y = m(o, e, x)$ 定义——智能体用它自己的模型、上下文与目标对输入 $x$ 采取行动。

LLM 智能体通常在多样数据集上预训练，以获得强大的基础知识底座；这一预训练过程赋予个体智能体基本技能与理解力，确保其能有意义地贡献于协作环境。此外，每个智能体还可配备自己独有的外部工具，如计算器与 Python 解释器。

推广到**多智能体协作系统 $S$** 时，包含以下要素：

- $\mathcal{A} = \{a_i\}_{i=1}^{n}$：LLM 智能体集合，$n$ 为智能体数量，可预定义，也可依据系统当前需求动态调整。
- $O_{collab}$：集体目标集合，可被切分为每个智能体独有的目标，确保与系统整体目标对齐。
- $\mathcal{E}$：共享环境，智能体从中获取上下文数据。在 LLM-based MAS 的情形下，环境可有多种形态，如**向量数据库**（vector-based databases）或**公共消息接口**（common messaging interfaces）。
- $\mathcal{C} = \{c_j\}$：**协作通道**集合，促进智能体之间的交互，使其能依据给定目标、环境与输入交换信息：
  $$y_j = c_j\big(\{a_i(o_i, \mathcal{E}, x_i) \mid a_i, o_i, x_i \in c_j\}\big)$$
  通道由其机制区分，包括**参与者（actors）、类型、结构与策略**。若两条通道在这些方面存在差异，则视为不同通道。作者假设智能体之间具有**共同基础**（common ground），即接口在它们之间可被清晰理解（例如所有智能体都使用英语且切题）。
- $x_{collab}$：系统所感知的输入。
- $y_{collab}$：系统的输出，建模为 $y_{collab} = S(O_{collab}, \mathcal{E}, x_{collab} \mid \mathcal{A}, \mathcal{C})$。

通过这一结构化工作流，LLM-based MAS 中的智能体能够自适应地协作：响应任务需求、相互学习、协调行动以实现共同目标。原文给出两个例子：一是在 [39] 中，协作通道通过**有向无环图**（Directed Acyclic Graph, DAG）预定义，每条边代表智能体处理并接收输出，使智能体得以在模拟的 Minecraft 游戏环境中有效协作完成任务；二是在 [67] 中，智能体之间的协作先被规划，然后再执行编码任务。

图 2 展示了智能体及其组件，以及多智能体协作的概念：每个智能体由作为神经处理器的语言模型 $m$、当前目标 $o$、环境 $e$、输入感知 $x$ 与相应输出／动作 $y$ 构成；框架的**中心关注点**是促成智能体间协调与编排的**协作通道 $\mathcal{C}$**，这些通道由参与者、类型、结构与策略定义。该框架具有灵活性，既能容纳既有方法，也能在统一结构下分析多样的 MAS。

由此，作者把协作按**发生阶段**分为三类——这是一个常被忽略但很有用的切分：

- **后期协作（late-stage）**：如把多个智能体的输出／动作 $y$ 集成（ensembling）以实现协作目标；多数投票（majority voting）即最直接的例子，类似集成学习。
- **中期协作（mid-stage）**：如以联邦式、隐私保护的方式交换多个模型 $m$ 的参数或权重。
- **早期协作（early-stage）**：包括但不限于为模型开发而共享数据、上下文与环境。

> **对照图 2 的右侧面板**：原文把上述阶段落到具体交换内容上——早期阶段为「上下文共享（context sharing）、数据交换（data exchange）、嵌入共享（embedding sharing）、模型共享（model sharing）、权重共享（weight sharing）」与「智能交换（intelligence exchange）」；后期阶段为「输出共享（output sharing）、目标共享（objective sharing）、任务共享（task sharing）」。这一层「到底共享什么」的粒度，比笼统说「协作」更便于工程落地。

### 4.2 问题定义

在 LLM 驱动的 MAS 中，智能体之间必须协作，共享一个共同目标或目标集合。每一次协作都有一条通信通道 $c$。协作包含三件事：1）把带有特定目标的智能体（两个或更多）依据其独特专长与资源**委派**（delegating）出去；2）**定义**它们协同工作的协作机制；3）智能体之间**决策**以达成最终目标。

$$y_{collab} = S(O_{collab}, \mathcal{E}, x_{collab} \mid \mathcal{A}, \mathcal{C}) = \big\{ c_j(\{a_i(o_i, \mathcal{E}, x_i) \mid a_i, o_i, x_i \in c_j\}) \mid c_j \in \mathcal{C} \big\} \tag{1}$$

其中每个 $c_j \in \mathcal{C}$ 代表一条通信通道，促成智能体 $a_i$ 依据各自输入 $x_i$ 的协作行动，使它们得以协同工作。**这里的「协同工作」超越了通信（信息交换）**，要求更深的协作行为，涉及协调与管理——这正是释放 MAS 能力的关键。

每条协作通道都是智能体协同工作的机制，由特定属性刻画：**参与者（actors，所涉智能体）、类型、结构与策略**。例如通道类型可以是竞争、合作或竞合；结构可以是对等、集中或分散。**任一属性的差异都会导致一条不同的协作通道**。举例来说，在一个对等结构的系统中，两个 LLM 可能相互竞争，而其他 LLM 相互合作；这些不同的交互类型导致各自独立的协作通道。这种灵活的通道框架使智能体能够调整其交互方式，在多样场景下优化多智能体协作效能与任务效率。

## 5. 方法论：协作机制五维度（核心章节）

### 5.1 总览

本章对 LLM-based 多智能体协作系统做广泛综述，强调其关键特征，包括智能体之间协调与编排的机制——即**协作通道**——的类型、策略与结构。图 2 给出了作者提出的 MAS 框架，细化了其核心组件与相互连接。

**综述策略**是：系统性地分析既有 MAS 研究，识别多智能体协作的定义性特征；由此推导 MAS 设计的基本组件与趋势，并综合为一个连贯框架。具体而言，系统中的每个 LLM 智能体都配备 LLM $m$、当前目标 $o$、环境 $e$、输入感知 $x$ 与相应输出／动作 $y$（对应图 2 左半部分，并在 3.1 节用数学记号形式化描述）。框架的**中心关注点**是智能体之间的协作通道 $\mathcal{C}$，它促成智能体间的协调与编排。这些通道由**参与者**（actors）、**类型**（如合作、竞争或竞合）、**结构**（如对等、集中或分散）与**策略**（如基于角色、基于规则或基于模型）刻画。协作机制横跨机器学习过程的多个层面，包括**数据交换、共享输入嵌入、模型共享与输出共享**，使智能体能够有效交互并借力彼此长处。

对每个组件，作者讨论文献中观察到的主流实现趋势与方法学，考察这些方法如何对齐所提框架，并在本章末尾总结主要发现与经验教训，为后续研究提供指引。

### 5.2 协作类型（合作 / 竞争 / 竞合）

#### 5.2.1 合作（Cooperation）

当智能体把各自的目标 $o_i$ 对齐到一个共享的集体目标 $O_{collab}$、协同工作以取得互利结果时，即发生合作：

$$O_{collab} = \bigcup_{i=1}^{n} o_i$$

智能体会评估彼此的需求与能力，主动寻求协作机会。此外，智能体也可被安排专注于其专长范围内的特定子任务，从而提升效率、缩短完成时间 [24]。在那些「协作式问题求解、集体决策与互补技能组合有助于达成单个智能体无法同样有效完成的复杂目标」的任务中，这类协作至关重要 [26, 29, 33]。

原文列举的代表工作：

- **[117]**：以**反馈回路**作为主要协作通道——任务先由一个 LLM（Actor，行动者）处理，再由 Evaluator（评估者）与 Self-Reflection（自反思）模型对输出与结果打分，产出面向 Actor 的**言语指导**（verbal guidance）以促其改进。
- **Theory of Mind for Multi-Agent Collaboration [75]**：智能体在环境 $\mathcal{E}$ 中获得**共享信念状态**（shared belief state）表示，帮助它们追踪彼此的目标与行动，从而促成更顺畅的协调与更好的协作结果。这种共享状态带来了 LLM 智能体的涌现协作行为与高阶心智理论能力，但在优化长程规划与管理幻觉方面仍存挑战。
- **AgentVerse [24]**：智能体在合作框架内专长于不同角色（如招募 recruitment、决策、评估），通过发挥各自独特专长提升系统效率。
- **MetaGPT [56]**：采用**流水线（assembly line）模型**，分配角色并把**标准作业程序**（Standardised Operating Procedures, SOPs）编码进提示 $r_i$，以增强结构化协调并产出模块化输出 $y_i$。MetaGPT 凸显了把人类领域知识融入 MAS 的潜力。
- 合作式方法在问答 [54]、推荐系统 [131]、协作编程 [60] 等领域取得成功——智能体以经理、搜索者、分析师等专业化角色协同达成复杂目标。
- **CAMEL [74]**：提供**角色扮演**（role-playing）框架，由一个任务特定智能体与两个协作 AI 智能体（User 与 Assistant）通过基于角色的对话完成任务。
- **AutoGen [134]**：使开发者能定义灵活的智能体行为与通信模式，让 LLM 智能体通过对话协作，并把复杂任务分解为可管理的子任务。

**合作的挑战**：智能体之间频繁通信与多条协作通道会增加计算成本与复杂度；在动态环境中，若没有定义良好的协作通道 $c_i$，协调多个智能体的行动也会很困难。虽然合作是主要目标，但若智能体对共享目标的理解不同、或情境需要动态适应，冲突仍可能出现。例如在 [91] 描述的**书市（book marketplace）应用**中，智能体可能表现不可预测——给自己发消息、假装成客户。合作型 MAS 的整体成功率还依赖于个体智能体的可靠性与性能：一个或多个智能体失效（如**无限对话循环**、放大的幻觉 [56]）会对整个系统造成负面影响。因此，**失效处理**（failure handling）与**可信性**（trustworthiness）等机制必须纳入考虑。

#### 5.2.2 竞争（Competition）

当存在冲突目标或有限资源的情境时，即发生竞争。在此类交互中，智能体优先考虑自身目标 $o_i$，这可能与他人目标冲突或对立，引入对抗要素：

$$O_{collab} = \{o_i \mid o_i \neq o_j, \forall i \neq j\}$$

不过，这种竞争仍可朝向集体目标 $O_{collab}$，例如辩论（debate）场景。在 LLM-based MAS 中，竞争动力学可出现在辩论或策略博弈等任务中，智能体寻求最大化自身的成功判据 [22, 155]。

**竞争的价值**：把竞争纳入协作型 MAS 可以激发创新、提升智能体响应的鲁棒性。竞争促使智能体发展更高级的推理与更具创造性的问题求解，并通过测试各智能体能力的极限来增强系统适应性。

代表工作：

- **LLMARENA [22]**：以竞争为主要协作类型的 LLM-based MAS，在**七个动态博弈环境**中被基准测试。例如在井字棋（TicTacToe）中，棋盘在环境 $\mathcal{E}$ 内以文本表示，两个 LLM 智能体通过系统提示 $r_i$ 被指示相互竞争、设法压过对方，因为它们的目标 $o_i$ 互斥。作者强调，LLM 智能体之间的竞争能够激发**空间推理、策略规划、数值推理、风险评估、通信、对手建模（opponent modeling）与团队协作**等技能；但也承认，由于 LLM 与其他行动者交互的内在能力有限，它们在成为完全自主智能体的路上仍有相当长的路要走，尤其是在对手建模与团队协作方面。
- **[155]（CompeteAI）**：模拟一个博弈环境，2 个智能体扮演两家餐厅经理，争夺 50 位顾客。精心设计的提示 $r$ 设定场景，为智能体环境 $\mathcal{E}$ 提供语境，并给出可通过 API（外部工具）访问的完整餐厅管理系统。每个智能体的上下文 $e_i$ 包含对手前一日表现的信息，包括菜单、顾客数量与反馈。此时两位经理之间的协作通道 $c$ 是竞争性的，展示了结构化竞争如何驱动智能体优化策略，且契合若干经典社会学与经济学理论。
- **LEGO [54]**：面向**因果解释生成**（causality explanation generation）的多智能体协作框架，其中竞争性协作连接 $c$ 同样是预定义的。协作由 2 个 LLM 构成，一个充当 Explainer（解释者）给出初始输出，另一个充当 Critic（批评者），进行迭代精炼与反馈。
- **[104]**：智能体之间的协作发生在**更早的训练阶段**——多个专家智能体被组合并一起训练，其目标让智能体为最佳候选答案相互竞争，并识别出在输入问题所属领域上训练过的智能体。

**竞争的挑战**：竞争可能引入冲突，需要机制确保竞争保持建设性、有益于整体系统目标。对竞争型协作而言，智能体间的有效协调尤为重要。如 [128] 所研究，若竞争性协作通道设计欠佳，MAS 方法在一系列推理任务与多种骨干 LLM 上，会被**带强提示（含相关少样本示例）的单智能体**反超。在期望合作的场景中，过度的竞争可能妨碍对齐，需要框架有效平衡二者。

#### 5.2.3 竞合（Coopetition）

竞合是合作与竞争的战略性混合，使智能体在某些任务上协作以实现共享目标，同时在其他方面相互竞争。这一概念虽相对较新，但已在近期研究中得到探索：

- **[2, 34]**：模拟**协商**场景，利益不同（有时冲突）的智能体进行权衡取舍，以达成互利协议。在这些场景中，智能体为其利益赋予不同价值，从而创造妥协与协作的机会。
- **混合专家（Mixture-of-Experts, MoE）框架**同样契合竞合类型 [6, 15]。在 MoE 中，多个专家模型竞争着为最终输出做贡献，由**门控机制**（gating mechanism）为每个输入选择最合适的专家。这一竞争性选择过程确保被选中专家的组合专长带来更优的整体模型性能。专家之间的竞合交互首先发生在模型**训练阶段**：它们被训练为在数据的不同方面专业化，从而增强模型有效处理多样任务的能力。

#### 5.2.4 不同协作通道类型的协调

在 LLM-based MAS 中，常常需要超越单一协作类型（如竞争或合作）的复杂交互。不同智能体可参与不同的协作通道 $\mathcal{C}$，各具不同交互类型，共同协调以实现系统整体目标 $O_{collab}$。这种**混合协作模型**结合了各协作类型的特征，借力各自长处来提升整体系统性能与适应性。

混合协作已在多种 LLM-based MAS 中得到探索：

- **LEGO [54]**：框架第一阶段由 3 个智能体**合作**增补当前任务的信息；第二阶段在 Explainer LLM 智能体与 Critic LLM 智能体之间建立**竞争**通道，以精炼其面向任务的输出。
- **[77]（MAD，Multi-Agent Debate）**：两个智能体 $a_1$ 与 $a_2$ 就某话题持相反观点进行竞争性辩论，试图说服**裁判智能体** $a_3$。$a_1$ 与 $a_2$ 之间的竞争性协作通道记为 $c_{comp}$，由所涉智能体与竞争性交互类型刻画；同时，$a_3$ 与 $a_1$、$a_2$ 均**合作**以达成最终决定，形成与辩论智能体群体之间的合作性协作通道 $c_{coop}$。

在 LLM-based MAS 中纳入多条交互类型各异的协作通道，丰富了交互动力学，增强了系统达成复杂目标的能力。这一设计反映了真实世界场景——多样交互共同促成成功结果——并为开发更精细、更可适应的 MAS 开辟了道路。然而，协调多条协作通道会引入复杂性。为管理混合协作的复杂度，**角色分配、通信协议与共享知识表示**等协调机制不可或缺。

### 5.3 协作策略（基于角色 / 基于模型 / 基于规则 / 混合）

一般而言，MAS 的协作策略有三类：1）**基于规则**（Rule-based）、2）**基于角色**（Role-based）、3）**基于模型**（Model-based）。图 4 给出三类策略的实例：在基于规则的例子中，智能体进行辩论并参与多数投票；软件项目是基于角色协议的实例；在游戏中，智能体在不确定环境中通信并做概率性决策。原文表 3 汇总了若干协作协议的研究。

#### 5.3.1 基于规则的协议（Rule-based Protocols）

$\mathcal{C}$ 中智能体之间的交互被**预定义规则严格管控**，确保智能体依据系统层面对可接受输入 $x_{collab}$ 的约束来协调行动。这类协议强制一种结构化的协作通道设置：智能体依据特定规则集行动，而非依据概率性或角色特定的输入。

代表工作：

- **[151]**：采用受**社会心理学**启发的规则型协议，智能体模仿人类的协作动力学，如辩论与多数决（majority rule），在不偏离预定义路径的前提下实现高效协作。
- **[162]（PoSE）**：提出一种**动态规则型协议**，利用预定义的事件触发条件来优化 LLM 驱动系统中的通信与协调。这类协议减少了智能体之间不必要的通信，同时通过清晰定义的交互规则维持有效协作（应用于具身智能体的语义导航，抑制感知噪声）。
- **[143]**：受**同行评审**（peer review）启发的协作机制，用预定义规则让智能体相互批评、修订与精炼彼此的输出，提升复杂任务中推理的精确度。
- **[21]**：MAS 中的**共识寻求**（consensus seeking）研究表明，规则型策略如何使智能体协商并对齐行动以走向共享目标，应用于多机器人聚合（multi-robot aggregation）任务。实验发现并讨论了**四种共识策略**、智能体人格与网络拓扑对「遵循规则倾向」的影响，以及最终结果，凸显了 LLM 驱动智能体在共识寻求中审慎而合作的本性。

**优点**：效率与可预测性。用一组预定义规则治理智能体交互，实现直接、便于调试——系统行为可被轻易追溯到具体规则。对于流程明确、变异性有限的任务（如共识寻求与导航）尤其高效。此外，预定约束有助于保证系统**公平性**，因为权力限制被施加于每个智能体 [151]。

**缺点**：缺乏适应性。面对预定义规则范围之外的意外情况或动态环境，系统可能无法恰当响应，或需要大量人工干预来调整规则集。而且随着任务复杂度上升，所需规则数量可能**指数增长**，使系统难以扩展与维护。

#### 5.3.2 基于角色的协议（Role-based Protocols）

基于角色的协议利用**预定义的角色或分工**，其中每个智能体 $a_i \in \mathcal{A}$ 在一个被切分的目标 $o_i \subset O_{collab}$ 上运作——通常基于其领域知识——以支撑系统总体目标。

代表工作：

- **AgentVerse [24]**：展示了为每个智能体分配特定职责的效力，模拟类人协作，并通过角色恪守（role adherence）强化对齐。该策略对 $\mathcal{C}$ 中每个智能体的角色进行分类，使其能主动且内聚地工作，避免职责重叠。
- **MetaGPT [56]**：通过编码**标准作业程序（SOPs）**把基于角色的协议形式化，每个智能体的角色由专家级知识定义，使智能体能作为专业化操作员彼此校验结果。该协议通过任务分发的模块化**防止错误传播**，即便在复杂项目中也能产出连贯输出。
- **RoCo [83]**：在多机器人等其他环境中，为 LLM 智能体分配**对话角色**。这类设置让专业化智能体通过优化规划与轨迹任务，提升物理交互的有效性。
- **BabyAGI [120]**：展示了任务创建与优先级排序中的不同角色如何提升框架内效率——智能体用三条不同的链（任务创建 Task creation、任务优先级排序 Task prioritization、执行 Execution）并行自主管理其任务。

**优点**：通过给每个智能体特定功能与任务集，基于角色的技术提升了 MAS 的效率与结构性。由于智能体被独立创建、实现与更新，这种显式分工促进了**模块化**并提高单个模块的**可复用性**，从而整体提升系统性能 [56]。因此该技术适合模拟具有明确定义的专业岗位的真实环境，如商业或技术场景。

**缺点**：若角色定义不当，基于角色的系统会表现出**僵化**，可能导致争执或功能缺陷。此外，智能体工作之间的**相互依赖**与系统性能内在绑定：不同角色的智能体之间通信不畅或交互阻塞，会严重损害系统整体效能。

#### 5.3.3 基于模型的协议（Model-based Protocols）

基于模型的协议为决策提供灵活性，尤其适用于「输入感知的不确定性可能影响智能体行动」的环境。在此结构下，决策的概率本性支撑每个智能体 $a_i \in \mathcal{A}$ 基于对输入 $x_{collab}$、当前环境数据 $\mathcal{E}$ 与共享协作目标 $O_{collab}$ 的分析，预测可能的结果。

代表工作：

- **[75]**：探讨概率模型——特别是通过**心智理论（ToM）推断**——如何让智能体做出考虑同伴可能心理状态的决策，即便智能体在 $O_{collab}$ 内目标分歧，也能改善任务对齐。该方法基于 ToM 预测有效分配各智能体的注意力，通过 $\mathcal{C}$ 中协作通道的概率性调整增强协调。
- **[16]**：尝试通过把**逻辑规则与 ToM 结合**来改进人机协作，以推断人类目标并引导智能体行动。该方法采用**概率逻辑推理**，把逻辑规则视为**隐变量**，并使用带 ToM 的**分层强化学习**模型，使智能体依据观察到的行为动态调整其信念与行动。通过把基于规则的**概率社会感知**与动态协作结合，所提框架有效应对输入感知的不确定性并促成稳健的任务表现——在 **Watch-and-Help** 与 **HandMeThat** 等基准上有显著提升，展示了该方法在复杂、部分可观测环境中的潜力。
- **[141]**：**概率图模型（Probabilistic Graphical Modeling, PGM）**框架丰富了 MAS 在 **Chameleon** 等游戏中的表现——智能体在共享协作通道内推断彼此的目标与理性程度。PGM 的引入使智能体能够处理模糊的上下文数据，在含不可预测变量的环境中提升多目标任务的表现。
- **[90]**：使用**概率时间自动机**（probabilistic timed automata）为智能环境中的状态转移建模，例如**自适应停车系统**——协作通道 $\mathcal{C}$ 依据智能体移动与时间敏感变量进行调整，实时优化交互。

**优点**：通过允许智能体基于对环境、共同目标与内在不确定性的感知做概率决策，基于模型的方法赋予 MAS 高度灵活性与鲁棒性。在智能体必须不断调整行为以适应变化的动态情境（如游戏与机器人环境）中尤其有效。由于可用概率推理确定最可能的行动路线，这类系统对噪声与未预见事件更具韧性。

**缺点**：更高复杂度是灵活性的代价。这类系统难以设计与部署，因为它们需要环境与智能体交互的复杂模型；概率决策可能带来计算开销高昂的流程，从而限制其在实时场景中的使用。

### 5.4 通信结构（对等 / 集中 / 分布式 / 分层）

LLM 智能体之间的通信结构（communication structures）指系统内**消息传递与信息交换的架构**。它规定智能体如何交互、共享信息与协调行动，以确保系统整体效率与可扩展性。原文指出，LLM-based MAS 依赖四类主要分布式结构（原文表述为 "four main classes"，但实际展开为三类）：1）**集中式通信**（Centralized）、2）**分散与分布式通信**（Decentralized & Distributed）、3）**分层通信**（Hierarchical）。

#### 5.4.1 集中式通信（Centralized Communication）

集中式通信采用**星型拓扑**（star-like topology），决策权集中于中心智能体，它管理控制与协调。$\mathcal{C}$ 由一组**参与-服务型（participating-serving）**连接构成，即若干参与智能体与一个中心「服务智能体」通信，服务智能体充当**枢纽（hub）**，负责管理、控制与协调各参与智能体。该结构可视为联邦学习（Federated Learning, FL）与 LLM 驱动系统的结合：在典型 FL 设置中，$n$ 个智能体协同学习一个最优模型 $m^*$，以最小化其在训练数据上的平均损失（这仍是当前主流做法，但其他范式也已出现——例如[92]的逐层聚合、[62]在服务端优化全局学习率、[8, 9]寻找不变梯度方向）。LLM-based FL 已有探索[163]，Google 也早已把 FL 用于在移动键盘数据上训练下一词预测[13, 142]。

具体实现：

- **LLM-Blender [64]**：在**一轮**中调用多个 LLM，再用基于 **pairwise ranking（成对排序）** 的机制合并 top 响应，把集中式协调通道用于提升输出质量。
- **[95, 106, 119]**：以类似的集中式协作，把工作负载分发给多个智能体、再拼接其答案；将任务提示的构造与求解分离（Meta-Prompting），或在众包式流程中汇总多智能体的中间产物。
- **AgentCoord [97]**：开源的**可视化协调策略设计工具**，用户可在统一界面中指定各智能体的角色、能力与协调方式；作者还开展用户研究以评估其可用性。
- **[164, 166]**：从多个智能体中**抽取知识**并综合成一张聚合图，通过「查询—搜索—回答」的迭代循环，在集中式协调下汇聚分散的知识。

集中式的优点与代价在表 4 中概括：实现简单、资源分配高效，但中心节点一旦失效，整个系统随之崩溃（韧性差）。

#### 5.4.2 分散式通信（Decentralized Communication）

分散式结构中，控制与决策**分散于多个智能体**，每个智能体依据局部信息与有限通信自主行动。该范式见于群体机器人（swarm robotics）、传感器网络与分布式 AI 等场景。$\mathcal{C}$ 由**对等（peer-to-peer）通道**构成，使智能体之间能交换信息而无需中心权威。

实现要点：

- **多智能体辩论**：多个 LLM 实例进行固定轮数的辩论，已被证明能提升事实性与推理能力[41, 77, 140]；[152] 则让智能体在**动态 DAG（有向无环图）** 结构中交互，拓扑本身随过程演化。
- **[24, 146, 151]**：最优通信结构**并非固定不变**，而会随任务与智能体组成而变化——同一个系统在不同任务上可能需要不同的拓扑。
- 代表系统：**MedAgent [122]**（多个专科医疗智能体各自发挥专长、协同诊断）；**MetaGPT [56]** 与 **ChatDev [105]**（分别模拟软件公司的产品经理、设计师、程序员等角色进行对等协作）；**MARG [32]**（多智能体论文评审）；**AutoAgents [20]** 与 **OKR-Agent [158]**（创作与分镜生成）；**SOA [59]**（自组织的超大规模代码生成，靠**增加智能体数量**来扩展）；**AgentCF [150]**（把用户与物品都建模为带记忆模块的智能体以做协同过滤）；**ProAgent [149]**（以 LLM 为「指南」，推断队友意图以协作）；**[99]**（带记忆的生成式智能体社会：存储经历、反思、按需检索）；**OpenAgents [139]**（Data Agent 用 Python/SQL 做数据分析、Plugins Agent 走 API、WebAgent 自主浏览网页）。

#### 5.4.3 分层通信（Hierarchical Communication）

分层结构中，智能体按**层**组织，各层功能不同，主要在同一层内或相邻层之间交互，以自底向上／自顶向下的方式传递信息与决策。

- **AgentVerse [24]**：用「**氢储能站选址**」案例说明分层协作——高层负责规划与决策，低层负责具体执行与信息收集。
- **DyLAN [81]**：把智能体组织成**多层前馈网络**，分两阶段：**Team Optimization**（依据任务查询，无监督地选出贡献最大的智能体）与 **Task Solving**（由选出的较小团队协作求解）；中间由 **LLM 驱动的 ranker** 动态停用低性能智能体，从而实现**推理时的智能体选择**与 **early-stopping（提前停止）**。
- **[74]**：把智能体集合视为一个**群体（assembly）**，层间组合产生整体能力。
- **[18, 41, 105, 132]**：均观察到**社会行为（social behaviors）自发涌现**——分工、协商与层级秩序在没有显式编程的情况下出现。
- **[146]**：提出**四种通信范式**——memory（记忆）、report（汇报）、relay（中继）、debate（辩论），分别对应 **bus（总线）、star（星型）、ring（环型）、tree（树型）** 拓扑，为结构选择提供了可操作的对照。

### 5.5 协调与编排（协调协议、对话规则、终止条件）

协调与编排（coordination and orchestration）指智能体之间**如何被组织与串联**。与前述「通信结构」相比，协调与编排更关心协作通道之间的关系：它们**如何被创建、如何排序、如何被刻画**。需要说明的是，原文在本节把协调与编排明确区分为**静态（static）**与**动态（dynamic）**两类，并指出不同 MAS 拓扑所适配的协调策略并不相同——例如顺序链式结构天然对应静态编排，而图式（graph-based）结构则需要动态编排。

#### 5.5.1 静态协调（Static Coordination）

静态协调在系统启动前就固定协作通道 $\mathcal{C}$ 的顺序与连接方式，依赖预定义规则与领域知识。适用于流程明确、可预先设计的任务。

代表工作：

- **顺序链（Sequential Chaining）[23]**：三个 LLM 智能体串联，第 $i+1$ 个智能体的输出为
  $$y_{i+1} = y_i \,\|\, x_i \,\|\, x_{collab}$$
  其中 $x_{collab}$ 为初始人类输入，$\|$ 表示拼接。前两个智能体扮演**领域专家**（给出互补视角），第三个负责**总结**。该方案在**大学理科选择题**上优于单智能体的 chain-of-thought 提示。
- **[135, 138]**：以顺序通道聚合多个智能体的输出，形成「接力式」协作。
- **MapCoder [60]**：模拟**程序综合**（program synthesis）的完整流程——recall（回忆相似题目）、planning（规划）、code generation（生成代码）、debugging（调试），每一步由不同智能体承担，通道顺序固定。
- **MACRec [131]**：为推荐任务设置 Manager（经理）、User Analyst（用户分析者）、Item Analyst（物品分析者）、Reflector（反思者）四个角色，静态规定它们之间的汇报路径。
- **文学翻译 [133]**：复刻传统**翻译出版工作流**（初译—审校—润色），以固定顺序的通道完成长文本翻译。

#### 5.5.2 动态协调（Dynamic Coordination）

动态协调让通道在运行中依据输入、环境或中间结果**自适应地生成与调整**，通常由**管理智能体（management agent）** 承担编排职责。

代表工作：

- **SPP（Solo Performance Prompting）[132]**：依据输入**动态识别人格**（persona），由管理智能体生成多个带定制系统提示的智能体，再综合它们的回答；GPT-4 被观察到具备较准确地识别所需人格的能力。
- **[61]**：**图式编排（graph-based orchestration）**——一个 LLM 驱动的 **Orchestrator** 依据用户输入构建 **DAG**（节点为任务，边为依赖与通道），再由 **Delegator** 汇总各节点结果。这使系统能处理宽度与深度都未知的复杂任务。
- **[33, 44]**：依据**输入本身**动态决定通道的组合方式（例如按问题类型调用不同专家）。

>
> | 类别 | 机制 | 优点 | 缺点 | 实现举例（Refs.） |
> |---|---|---|---|---|
> | **静态 Static** | 静态的通道列表 + 先验知识 | • 执行一致<br>• 能利用领域知识 | • 依赖初始设计的准确性<br>• 固定通道难以扩展 | 预定义规则、领域知识；顺序链 [23, 135, 138]、代码生成 [60]、推荐 [131]、文学翻译 [133] |

### 5.6 小结与经验教训

原文在本节给出六条可供后续研究与实践参考的经验教训（lessons learned），并指出了一个根本性事实：**LLM 本质上是独立的算法，并非为协作而训练**；因此多智能体协作的收益不是自动出现的，需要显式的机制设计。

1. **有效的协作通道至关重要。** AutoGen [134] 等框架表明，设计良好的协作通道可以让多智能体系统**超越单个智能体**；但反面证据同样明确：[128] 发现若协作通道设计不佳（提示、角色或终止条件不当），多智能体方法会被**带强提示（含相关少样本示例）的单智能体**反超。
2. **集体领域知识（collective domain knowledge）** 是 MAS 的核心价值来源：把不同专长的智能体组织起来，可以覆盖单个模型知识盲区。
3. **自适应角色与通道分配**：角色与通道不应一成不变，[39] 等工作显示按任务动态分配能显著提升效果。
4. **选择最优协作策略**：基于规则、基于角色、基于模型三类策略各有适用边界（见 5.3 与表 3），没有普适最优。
5. **可扩展性（scalability）**：智能体数量增加带来通信与协调开销，成本、可扩展性与效率是系统设计的关键约束。
6. **伦理与安全**：协作会放大幻觉、偏见与对抗风险（详见第 7 章）。

原文还列举了当前主流的开源框架：**AutoGen [134]**、**CAMEL [74]** 与 **crewAI**，它们为快速搭建多智能体协作提供了工程基础。

## 6. 应用场景

原文把 LLM 多智能体协作的应用归纳为**三大领域**：1）**5G/6G 与工业 5.0**（含物联网 IoT）；2）**自然语言生成（NLG）**；3）**社会与文化（S&C）**。表 6 列出各领域涉及的代表性方法，包括 LLM-SC [130]、LaMoSC [157]、LAM-MSC [65]、GMAC [160]、LLM-Blender [64]、SOT [95]、Meta-Prompting [119]、MAD [77]、FORD [140]、ChatDev [105]、AgentVerse [24]、AgentCoord [97]、OpenAI Swarm、TE [36]、AgentInstruct [88]、SocialMind [144]、CulturePark [73]、Mango [94] 等。

### 6.1 5G/6G 网络与工业 5.0

#### 6.1.1 面向 6G 的语义通信与网络智能化

LLM 驱动的多智能体协作被用于**语义通信（semantic communication）** 与网络资源管理：

- **LLM-SC [130]**：用 LLM 对传输文本的**语义概率**建模，在语义级与**技术级（technical-level）** 性能之间取得平衡——既提升语义保真度，又不牺牲链路层指标。
- **LaMoSC [157]**：**多模态融合语义通信**框架，利用 LLM 的外部知识生成提示文本，并用**融合编码器**通过注意力机制整合文本与视觉特征，从而在带宽受限时优先传输语义关键信息。
- **LAM-MSC [65]**：以**多模态对齐（Multimodal Alignment, MMA）** 为核心，基于多模态语言模型（MLM），借助 **CoDi** 完成模态转换，构建**共享多模态空间**，并以 GPT-4 作为知识库支撑语义对齐。
- **M2GSC [145]**：把 LLM 当作**共享知识库**，设置三个角色——复杂任务分解、语义表示规范、语义翻译与映射，从而在通信双方之间建立共同的语义基准。
- **GMAC [160]**：对齐观测状态与自然语言语义，通过**压缩语义通信**提升带宽效率。
- **MSADM [121]**：面向**动态异构网络**的端到端健康管理，覆盖**异常检测、故障诊断与缓解**三个环节，LLM 作为协调各环节的「促进者（facilitating agent）」。
- **[78]**：把 LLM 与**可重构智能表面（RIS）** 结合，用于车联网（Internet of Vehicles）的**资源分配**与**信号解码顺序**决策。

#### 6.1.2 工业 5.0 与物联网

工业 5.0 强调人机协同与个性化，LLM 多智能体被用于智能制造、智能家居与边缘智能：

- **[137]**：面向 IoT 的 LLM 系统，把开源 LLM **本地部署**，包含提示管理模块、后处理模块与任务特定提示库，重点解决隐私、安全与可扩展性。
- **SAGE [111]**：**智能家居**中的具身执行（grounded execution）智能体，动态构建一棵 **LLM 提示树**，据此决定下一动作、评估执行是否成功、并判断何时终止——是「对话规则 + 终止条件」在真实设备上的落地。
- **[112]**：**边缘分布式学习**，把路网切分为子图分配给各 **RSU（路侧单元）**，并以 **LSGLLM** 加入时空模块以建模交通动态。
- **[114]**：LLM 与 **Internet of Senses（感官互联网）** 结合，边缘智能体生成 **WebXR** 代码，在头显中可视化 3D 对象并估计多感官媒体数据。
- **CASIT [159]**：以多个 LLM 组成**集体智能**做数据分析与异常检测，通过逐步摘要与分类生成结构化报告。

### 6.2 问答与自然语言生成

这是 LLM 多智能体协作最先落地的领域，原文从**系统框架**与**评估范式**两条线索展开。

**（1）主流框架**

- **OpenAI Swarm**：以 **routines（例程）** 与 **handoffs（移交）** 为核心原语——每个 agent 由「指令 + 工具」定义，可在对话中把控制权**移交**给另一个 agent。设计刻意保持轻量、无状态，便于快速原型。原文以**客服售后退款**为例（图 7）说明：接待 agent 识别意图后把会话移交给退款专员 agent，后者调用退款工具完成操作。
- **Microsoft Magentic-One**：以 **Orchestrator（编排者）** 做高层规划、进度跟踪与**动态重规划**，把子任务委派给具备浏览器、本地文件、Python 执行等能力的专用子智能体——是 5.4.3「分层式」与 5.5.2「动态编排」的典型工程实现。
- **IBM Bee Agent Framework**：开源框架，支持 IBM Granite、Llama 3 等模型，提供模块化的预置组件（agents、tools、memory、instrumentation），并支持**智能体状态的序列化**，从而可暂停与恢复长任务。
- **LangChain Agents**：以工具调用与链式组合为特征，是应用最广的通用开发框架之一。

**（2）评估范式：用智能体评智能体**

- **Agent-as-a-Judge [165]**：让**智能体系统去评估另一个智能体系统**，提供全流程、细粒度的反馈，在成本与时间上远低于人类评估。它采用**基于角色（role-based）** 的策略、**去中心化**结构；作者构建了 **DevAI** 基准，包含 **55 个真实的 AI 开发任务**，实验显示其与人类专家判断的一致性优于 **LLM-as-a-Judge**。
- **Benchmark Self-Evolving [129]**：让多个智能体协作**改写基准实例**（改变上下文或问题本身以生成更难版本），角色包括 instance pre-filter（实例预筛）、creator and verifier（创建者与校验者）、candidate option formulator（候选选项构造者），覆盖数学、逻辑与常识推理，用于缓解**数据污染（data contamination）**。
- **Orca-AgentInstruct [88]**：用三条 **agentic 流**合成指令数据——Content Transformation（内容转换）、Seed Instruction Generation（种子指令生成）、Instruction Refinement（指令精炼），采用**去中心化**协作；用合成数据微调 **Mistral 7B**，在多项基准上最高带来 **54%** 的提升。

### 6.3 社会与文化领域

**（1）社会模拟与社会科学**

- **[3, 11]**：LLM 有潜力增强社会科学研究方法，但训练数据**缺乏全球心理多样性**，直接用于跨文化结论需谨慎。
- **[89]**：把社会互动视为**戏剧表演（theatrical performance）**，为智能体设定办公室职员、家庭成员等角色，使用 **GPT-4、Qwen2.5-14b、Llama-3-8b** 等模型观察其互动。
- 涌现出的社会能力包括：多轮对话、**心智理论（Theory of Mind）**[2, 75]、**霍布斯式社会契约论**下的规范形成[31]、以及对**非言语动作**的推断[79, 147]。
- 社会应用：[5, 36] 用 LLM 智能体**替代人类被试**做实验；[88] 生成合成数据；**SocialMind [144]** 在 **AR 眼镜**上部署社会感知智能体；[48] 增强**基于智能体的建模（ABM）**；[10, 148] 用于**政策干预**模拟；[53] 做**规范违反检测**。

**（2）文化**

- **CulturePark [73]**：多智能体协作生产**文化内容**并模拟跨文化交流。
- **Mango [94]**：面向文化领域的多智能体系统。
- **[103, 126]**：研究**文化演化（cultural evolution）**——智能体群体中的规范与偏好如何随时间变化。

**（3）该领域的局限**

原文明确指出三点：[36] 指出智能体实验中存在**信息不对称**问题[161]；[89] 指出**竞争与冲突消解**仍是难点；[109] 强调该领域**亟需标准化基准**，否则不同研究之间难以比较。

## 7. 开放问题与讨论

### 7.1 通往人工集体智能

**人工集体智能（Artificial Collective Intelligence）** 是本文的终极关切。原文引用 [71] 的定义，把由多个 LLM 智能体组成的系统视为一种**「数字物种」（digital species）**——它们具备交流、协作与共同演化的潜力。要实现这一愿景，至少需要解决四个层面的问题：

1. **统一治理（unified governance）**：包括**角色分配**（谁负责什么）、**失效检测与恢复**（某个智能体出错或掉线后系统如何自愈）、以及**冗余／后备智能体**（redundant / fallback agents）的编排。当前系统的角色多是人工预设，缺少运行时治理。
2. **共享决策（shared decision making）**：现有系统多采用**独裁式（dictatorial，由单一裁决者拍板）** 或**多数投票（popular voting）**，难以捕捉智能体之间的**偏好差异**，也无法在聚合时处理**过度自信**（把多个过度自信的判断简单投票，只会放大错误）。
3. **智能体作为「数字物种」**：一旦智能体长期共存与交互，**幻觉会经协作扩散并被放大**，还可能遭遇**对抗攻击**；作者提到 **Gemini 2.0** 是针对协作场景设计的尝试，说明工业界已开始正面回应这一问题。
4. **可扩展性与资源维护**：智能体数量增长会带来**记忆与算力**的线性甚至超线性开销，出现通信**瓶颈**；目前尚缺类似「MAS 缩放定律（scaling laws）」的定量规律。此外，**发现意外泛化（unexpected generalization）** ——系统展现出设计者未预期的能力——既是机会也是风险。

### 7.2 全面评估与基准

原文对评估现状的判断相当直接：**系统性评估多智能体系统的努力仍然很少**[80]。具体缺口包括：

- **指标过窄**：多数工作只看任务**系统性能**[155]，缺少对**协调效率**与**情境适当性（contextual appropriateness）**[17] 的度量。
- **缺少根因分析**：需要**细粒度**的归因方法[63]，判断失败究竟源于单个智能体、协作通道还是编排逻辑。
- **场景狭窄且不可比**：现有评估多在**很窄的场景**中进行，且各研究的**配置不一致**（模型、轮数、提示各不相同），导致结果**无法横向比较**[18, 22, 34]。
- **缺少标准化协议**：没有统一的交互协议与评测流程。
- **静态基准的风险**：静态数据集存在**数据泄漏（data leakage）** 与**过拟合**风险[102]，因此需要**动态基准**——让基准随模型能力演化而升级（这也正是 6.2 中 Benchmark Self-Evolving [129] 的动机）。

### 7.3 伦理风险与安全

- **幻觉经交互放大**：单个 LLM 的幻觉在多智能体对话中会被反复引用与「确认」。原文指出两大因素：LLM 的**过度自信**[151]，以及智能体之间的**误解（misunderstanding）**。
- **对抗攻击**：恶意输入或被污染的智能体可污染整条协作链[115]。
- **欺骗人类（deception）**：智能体可能学会策略性欺骗[7, 35, 84]，在竞争型或竞合型设置中尤其值得警惕。
- **拟人化导致的过度依赖**：智能体表现出类人特征时，用户容易**过度信任**[161]。
- **监管**：原文提到 **EU AI Act（欧盟人工智能法案）**，提示多智能体系统的责任归属与合规问题已进入立法视野。

## 8. 结论

原文的结论可以概括为三点：

1. LLM 多智能体协作已从「多角色对话」的原型阶段，发展为覆盖**通信、协调、编排**的工程体系，并在 5G/6G、自然语言生成、社会文化模拟等领域出现实证应用。
2. 作者提出的**五维度框架**——**参与者（actors）、类型（types）、结构（structures）、策略（strategies）、协调机制（coordination mechanisms）**——提供了一个**可扩展的分析透镜**：既能刻画已有系统（例如把 MetaGPT 描述为「角色型策略 + 分散式结构 + 静态编排」），也能指导新系统设计（先定类型，再选结构，最后定编排）。
3. 通往人工集体智能的关键瓶颈不在单模型能力，而在**治理、共享决策、评估与安全**这四项系统性工程。

## 9. 核心要点

1. 这是一篇**以框架为中心**的综述：用「参与者—类型—结构—策略—协调」五个维度统摄 200 余篇多智能体协作文献。
2. 「协作」在原文中有严格定义——$n$ 个智能体的目标被对齐到共享集体目标 $O_{collab}$，而非仅仅并发执行。
3. 协作类型分为**合作、竞争、竞合**，且真实系统常**混用**（LEGO 先合作后竞争，MAD 让辩论者竞争、让裁判合作）。
4. 协作策略分**基于规则、基于角色、基于模型**三类，分别以可预测性、模块化、适应性见长，各有明确失效边界。
5. 通信结构分**集中式、分散式、分层式**：集中式简单但脆弱，分散式可扩展但开销高，分层式瓶颈低但延迟与复杂度高。
6. 结构不是越新越好——[24, 146, 151] 的证据表明**最优拓扑随任务与智能体组成变化**。
7. 协调与编排的核心区分是**静态**（顺序链、预定义 DAG）与**动态**（管理智能体、按输入生成 DAG）。
8. 顺序链式多智能体（[23]）在理科选择题上可**优于单智能体 chain-of-thought**，说明「分工 + 汇总」本身即有效。
9. 反面证据同样重要：协作通道设计不佳时，多智能体方法会被**带少样本示例的单智能体**[128] 反超。
10. DyLAN [81] 的 Team Optimization + 动态 ranker 是「推理时选择智能体」的代表实现，兼顾精度与成本。
11. 应用侧已形成三条主线：**语义通信/工业 IoT**、**NLG 与评估**、**社会文化模拟**。
12. 最大风险是**幻觉沿协作链放大**，最大缺口是**缺少统一、动态、可比的评估基准**。

## 11. 评价：亮点、局限与启发

### 亮点

1. **框架化程度高**：把散落的多智能体工作收敛到五个可组合的维度，读者可以据此为自己的系统「定位」，这是本文相对早期综述（如仅按应用罗列）的最大增量。
2. **不回避反例**：明确引用 [128] 指出多智能体可能不如强提示单智能体，也指出 [24, 146, 151] 关于「最优拓扑依任务而变」的结论，避免了「多智能体必然更好」的叙事偏差。
3. **策略—结构—编排的层次清晰**：把「谁和谁说话（结构）」与「话怎么被安排（编排）」分开讨论，是工程上最有用的切分。
4. **表格密度高**：表 2–表 6 每张都以「定义—优点—缺点—代表工作」四栏组织，可直接当作设计检查清单使用。
5. **应用覆盖面广**：从语义通信到 AR 社会感知，说明协作机制并非只在聊天场景有意义。

### 局限

1. **分类维度存在重叠**：结构（集中/分散/分层）与编排（静态/动态）在实践中高度耦合，同一系统常同时属于多个格子；文中未给出判定优先级，读者容易归错类。
2. **「四类结构」与实列三类不一致**：5.4 开头称有四类主要结构，正文只展开集中式、分散式、分层式三类，属于明显的表述疏漏（可能是删节所致）。
3. **证据强度参差**：大量结论以「某文献报告有效」的形式并置，缺少对实验规模、基线强弱、可复现性的统一审视；尤其[23]「顺序链优于单智能体 CoT」这类结论，依赖具体任务与提示，难以外推。
4. **分类框架偏描述性、缺预测力**：五维度能描述已有系统，但未回答「给定任务该选哪种结构」——没有形成可检验的设计准则或定量模型。
5. **覆盖偏 2024 年前后**：对 2025 年兴起的新范式（如更强的工具使用协议、长程自治智能体）着墨有限；对成本模型、延迟等工程指标的定量讨论也较少。

### 对做多智能体系统的工程启发

1. **先定终止条件，再谈编排**：SAGE [111] 与 AutoGen 的经验都表明，缺少明确的成功判据与终止条件，系统会陷入无限对话或过度迭代；终止条件应是设计的第一等公民。
2. **默认从「顺序链 + 单裁判」起步**：静态编排（[23] 式流水线）实现成本最低、可调试性最好；只有在任务宽度/深度事先未知时才引入动态 DAG（[61] 式编排）。
3. **把「拓扑」当超参数而非架构**：[24, 146, 151] 的证据说明拓扑需按任务搜索；工程上应把结构做成可配置项，用小规模实验选型。
4. **用去中心化评估替代单一指标**：Agent-as-a-Judge [165] 提示可以把评估本身做成一个多智能体流程，用细粒度反馈定位失败环节，而不是只看最终准确率。
5. **显式设计失效处理**：冗余智能体、超时重试、幻觉交叉校验应当内建于协作通道，而非事后补丁——这是 7.1 节「统一治理」在工程上的最小可行形态。
